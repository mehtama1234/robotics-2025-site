01 · the problem

You can't list every thing

For a decade, recognition meant choosing from a fixed list. Train a network on a thousand classes and it will happily label any of those thousand — but show it the one thing you forgot to include, and it has no choice but to force a wrong answer from its list.

The world doesn’t come with a finite menu. New objects, rare objects, oddly-described objects — a robot in a real kitchen meets things no label set anticipated. Open-vocabulary perception is the escape from the fixed list: recognize, detect, and segment things described by any words, including ones never seen in training.

the actual math — one level deeper

Closed-set classifier: softmax over K fixed classes — any input is forced onto one of the K, so an unseen category is always mislabeled.

Open-vocabulary: score the input against embeddings of arbitrary text, so the label set can grow at test time without retraining.

02 · the key idea

Put pictures and words in one space

The idea that broke the wall is deceptively simple. Train two encoders together — one for images, one for text — on hundreds of millions of caption pairs, so that a picture and its description land at the same place in a shared embedding space.

Once images and words share a space, recognition stops being a fixed classifier and becomes a lookup: embed the picture, embed any set of words you like, and pick the nearest. Add a new category by simply typing its name — no retraining. This vision-language embedding (CLIP and its kin) is the engine under everything that follows.

the actual math — one level deeper

Contrastive training pulls matching image-text pairs together and pushes mismatches apart, aligning both encoders in one space.

Recognition: label = argmax over candidate texts of cosine(image embedding, text embedding) — a nearest-neighbour lookup over any vocabulary.

03 · detect & segment

Box anything you can describe

Recognizing a whole image is one thing; finding where things are is what a robot needs. Open-vocabulary detection and segmentation take region proposals — candidate boxes or masks — and score each against arbitrary text embeddings rather than a fixed classifier head.

So you type ‘the laptop’ (or ‘a small blue mug’) and the regions that match light up, even for categories never in the training labels. The words are supplied at test time, which means the same model handles an open, growing set of things to look for — the practical form open-vocabulary usually takes.

the actual math — one level deeper

For each region proposal r with feature v_r, score s(r,t) = v_r · t for each prompt embedding t; keep boxes above threshold, label by best t.

Training often distills a VLM’s features into the detector so region features live in the shared image-text space.

04 · grounding

The one I mean, not just the class

Detection finds all the cups; language usually means one of them. ‘The red mug behind the laptop’ is a referring expression, and resolving it — grounding — means picking the exact region the words point to, not just the category.

That takes reasoning over attributes (red), and spatial relations (behind the laptop), to disambiguate among look-alikes. Grounding is what turns open-vocabulary perception into something a person can actually direct: say what you mean in plain language, and the system points at the right thing.

the actual math — one level deeper

Referring: pick the region maximizing a match(region, phrase) that accounts for attributes and relations, not just the class.

Relations (‘behind the laptop’) require reasoning over pairs of regions — grounding resolves to the single intended referent.

05 · into 3D

A map you can ask by name

For a robot, recognition has to live in space. The final step lifts language-aligned features off flat images and into a 3D map — attaching a CLIP-style feature to every point, voxel, or Gaussian using the camera geometry.

Now the map itself is queryable by language: ask ‘where is the sink?’ and the matching region in 3D lights up, even though no one labelled a ‘sink’ when the map was built. This open-vocabulary 3D field is where perception meets navigation and manipulation — a spatial memory you address with words.

the actual math — one level deeper

Lift 2D features to 3D: for each 3D point X seen in image pixels, aggregate the pixels’ language-aligned features into a per-point descriptor F(X).

Query: score F(X) · t against a text embedding t to localize ‘the sink’ in the map — open-vocabulary, no 3D labels needed.

Vision-language embeddings (the CLIP idea)

both
the problem

Images and words live in separate numeric spaces — a picture is a pixel grid, a word is a token id — so you cannot directly compare them. The gap means a classifier must enumerate every category it will ever see.

the approaches

The foundation: train image and text encoders together so a picture lands near its description in one space, and recognition becomes a text lookup. Everything else here builds on this alignment.

Work refines the embedding for dense, spatial, and synonym-stable use.

worked example — one concrete run
  1. Input pair: a 224×224 photo of a coffee mug + caption ‘a ceramic mug’
  2. Image encoder (ViT-L/14): 196 patch tokens → 768-d CLS feature, L2-normalized to unit sphere
  3. Text encoder (transformer): ‘a ceramic mug’ → 77 tokens → 512-d feature, L2-normalized
  4. Cosine similarity: dot product = 0.31 for match, ≈0.04 for random unrelated pair
  5. Contrastive loss: pull matched pair together, push 4095 other pairs in batch apart; temperature τ=0.07
  6. At test time: embed ‘a ceramic mug’, ‘a chair’, ‘a dog’ → argmax cosine against the photo → ‘a ceramic mug’ wins at 0.31

the problem

  2. Region proposals: RPN generates ~2,000 candidate boxes; NMS keeps ~300
  3. Region feature: RoI-align each box → 7×7×2048 → 512-d vector, L2-normalized

Open-vocabulary segmentation

vision
the problem

Classification aligns a single global image feature to a word; segmentation must align every pixel, or every mask proposal, to words — a much harder version where global image-text training fights the pixel-level detail you need.

the approaches

Label every pixel by open text — semantic, instance, or panoptic — the dense version of the problem, where global image-text alignment fights pixel-level precision.

Objectness bias, region-text alignment, and cost aggregation are the battlegrounds.

worked example — one concrete run
  1. Image: 512×512; CLIP ViT-L/14 extracts patch features: 32×32 patches × 1024-d each
  2. Text: encode ‘plant’ → 1024-d text embedding T
  3. Pixel-text scores: for each patch (i,j), compute cos(F_ij, T) → 32×32 heatmap
  4. Upsample + refine: bilinear 32×32 → 512×512; apply DINO attention map to recover sharp boundaries
  5. Threshold at 0.45: 11,240 pixels assigned to ‘plant’; largest connected component = 1 mask
  6. Panoptic merge: repeat for all prompts, resolve overlaps by max-score wins → final labeling

Part IV

Where it stands

Naming anything by language is a young superpower with rough edges. What is genuinely still hard:

Dense precision from a global model. VLMs are trained on whole-image alignment, which fights the pixel-level precision segmentation needs — background bias and geometric drift persist.
Rare words & fine parts. Open vocabulary is strong on common objects but weak on rare descriptions, fine-grained parts, and compositional phrases (‘three to the left of’).
Real-time at dense resolution. Per-pixel VLM inference is slow; sliding-window accuracy costs a large slowdown, and edge deployment forces hard trade-offs.
Feature drift & hallucination. VLM embeddings drift across domains and sessions and confidently mislabel; there is no principled uncertainty for a grounding failure.
Geometry the language ignores. Language names things well but reasons about exact distance and reachability poorly — robot use still needs separate geometric grounding.
Domain shift. Remote-sensing, underwater, thermal, and medical imagery break off-the-shelf features; generalizing across domains stays brittle.
