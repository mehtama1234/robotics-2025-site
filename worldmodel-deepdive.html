The big picture — connecting the dots

The core problem running through this group of papers is straightforward but hard: a robot decides what to do by imagining the future, so it needs an internal model that predicts how the world will change when it acts. But that model only works inside situations it has been trained on — the moment something new or hidden appears (a heavier object, a slippery floor, a person walking in), the model's predictions go stale and the robot does not know it, leading to failure. The field's working bet is that a world model — a learned prediction engine trained to forecast what happens next — can be both fast enough to run on a robot and honest about what it does not know, so the robot can plan safely by imagining outcomes before acting and can detect when it has stepped outside familiar territory.

Four things people are actually trying to do with it:

  • ① Learn to predict and plan inside that prediction. LUMOS trains a robot to imagine task execution inside a learned world model, using language and image goals to label experience; LIMT extends one world model across multiple tasks so the robot can transfer learned skills; X-MOBILITY learns from unlabeled video, then fine-tunes control on a small set of human examples.
  • ② Know when the model is wrong. Privileged-Dreamer watches the robot's own sensor history to estimate hidden variables (payload, friction) that shift the physics; Bounding Distributional Shifts detects when a planned action would venture into unfamiliar territory and discards unsafe plans.
  • ③ Reduce the expensive burden of labeled data. Imitation Learning with Limited Actions via Diffusion Planners splits the job: a diffusion model plans over observed states without action labels, and a small learned controller translates those plans into motor commands using a compact structure that stays stable.
  • ④ Plan by picturing the future, not abstract numbers. RoboEnvision generates a video of task steps, extracting joint angles from the snapshots; Chain-of-Imagination breaks long instructions into visual targets, so each step is concrete. SR-AIF and Curiosity-Driven Imagination use the robot's own uncertainty to guide what it learns — letting it explore toward things it does not yet understand.

The throughline: the field is learning to build prediction models that robots can actually trust and use on real hardware — models that admit what they do not know, run fast, and stay honest when the world surprises them. The 2025 work is people tackling speed (model compression, efficient planning), honesty (uncertainty quantification, out-of-distribution detection), and data efficiency (imagination rollouts, diffusion planning, curiosity) so a robot's internal picture of the future becomes reliable enough to base real decisions on. Still open: running good world models on tiny hardware in real time; merging predictions with true uncertainty estimates that hold across task variations; and catching distribution shift fast enough for the robot to react before committing to a bad plan.

The problem — in depth

A robot arm reaching for a cup does not face one clear best path. There are dozens of paths that all work. A human picks one without thinking. A robot needs a method that can hold all those valid options in mind and then commit to one of them smoothly.

The oldest approach is to compute an average: if a robot has learned from many examples of humans doing a task, it can try to pick the action that sits in the middle of what humans did. That works when there is one clear answer. When there are many equally good answers, averaging collapses them into something that is none of them — like averaging a vote of "go left" and "go right" and ending up going straight into a wall. The robot freezes, twitches, or follows a shaky in-between path that makes real tasks fail.

The broader problem runs deeper. A robot has to do four things at once: take in a messy, changing world through cameras and sensors; build a picture of what is happening; decide what to do; and move a physical body to do it — all in real time, on limited power, without breaking anything or anyone nearby. Each of those four steps has its own hard problems. This topic sits at the crossing of all four.

The specific hard point here is that the world the robot must model and act in is full of gaps. Cameras only see surfaces. Sensors go noisy. Hidden things — the weight of an object, the slip of a floor, the position of a person who just walked in — change the physics of the task. A robot that builds an internal model of what will happen next (called a world model) can plan ahead without touching the real world, but only if that model is honest about what it does not know and can update fast when something new appears.

The field has spent years watching robots fail at tasks they seemed to understand in training and break completely the moment something small changed — a different table surface, a slightly heavier object, a new room layout. The root cause is almost always the same: the robot's internal picture of the world is wrong, and it has no good way to know that it is wrong or fix it.

The approaches — how the field actually tackles it

Building and using an internal model of the world

Several papers train the robot not just to act but to predict what happens next — to build a model inside its own computing that simulates the effects of its actions before it takes them. This internal model (a world model) lets the robot plan in its head, practice situations it has never seen in real life, and catch bad plans before they cause real damage.

LUMOS uses a world model to let a robot practice tasks in simulation that never appeared in the original recorded data, using language and image goals to label that experience in new ways. LIMT extends the same idea across many tasks at once: a single world model absorbs language instructions so the robot can share what it learned in one task to help with another. X-MOBILITY trains a world model to understand environments from large amounts of unlabeled data, then adds a smaller set of human examples just for the control step, so it can handle new environments without retraining from scratch.

The payoff is that a robot with a good world model is not limited to situations it has practiced. It can reason forward and reject bad options before they happen.

Catching hidden changes and unfamiliar situations

A world model is only trustworthy inside the situations it was trained on. When something new appears — a heavier load, a slippery surface, a person behaving unexpectedly — the model's predictions go wrong and the robot does not know it.

Privileged-Dreamer addresses this by having the robot watch its own recent history of sensor readings and actions and use that to estimate hidden variables (things it cannot measure directly, like payload or friction). Those estimates feed both the robot's decision and its internal model, keeping both aligned with what is actually happening. Bounding Distributional Shifts takes a different angle: before the robot commits to a plan, a small detector checks whether the plan would take the robot into situations it has never seen. If it would, the plan is discarded. These two approaches — estimate the hidden thing, or detect when you are lost — together let the robot stay honest about the limits of its knowledge.

Reducing the need for labeled data

Training a robot usually means recording thousands of examples that log exactly what action the human took at every moment. That is expensive and slow to collect.

Imitation Learning with Limited Actions via Diffusion Planners and Deep Koopman Controllers splits the job in two: a diffusion model (a method that works by starting from noise and gradually refining it into a good output) plans over states that the robot can observe, without needing action labels. A second, smaller controller — trained on only a handful of labeled examples — translates that plan into actual motor commands using a compact mathematical structure (Koopman operator) that stays well-behaved. The result is that the expensive labeled data requirement drops sharply.

Planning by imagining future pictures

Rather than reasoning in abstract numbers, some approaches plan by generating pictures of what the world should look like at each step of a task, then steering the robot toward those pictures.

RoboEnvision generates a short video of a task in key snapshots, fills in the motions between them, and then reads off the joint angles the robot needs. Chain-of-Imagination uses a language model to break a long instruction into steps and an image generator to create a visual target for each step, so the robot always has a concrete picture to move toward. This approach makes long, multi-step tasks easier to handle because each step becomes a clear local target rather than a vague direction.

Letting curiosity guide what the robot learns

SR-AIF and Curiosity-Driven Imagination both address the case where the robot only gets a signal when it actually succeeds at a task — which happens rarely when it is first learning. SR-AIF uses a method called active inference, which drives the robot to act in ways that reduce its own uncertainty about the future, pushing it naturally toward goal states even without frequent rewards. Curiosity-Driven Imagination adds a curiosity module that points the robot toward situations it does not understand yet. When it finds something new, a high-level planning system adds a new rule to its knowledge and generates a training signal to teach the robot the motion that goes with it.

Where it stands

World models and diffusion-based planning have moved from research curiosities to methods that beat older approaches on real robot tasks, especially when the supply of labeled data is limited or the environment changes. The main gaps that remain are speed — world models are still expensive to run on small onboard computers — and reliability outside the situations they were trained on. Detecting when a model's predictions have gone stale is a solved problem only in narrow cases. Combining fast models, good uncertainty awareness, and broad coverage of real-world variation in a single system is still open work.

LUMOS: Language-Conditioned Imitation Learning with World Models

ICRA 2025 · 4 citations · sub-approach: build and use an internal world model to plan in latent space (imagination rollouts to reduce covariate shift)

What it does

LUMOS trains a robot manipulation policy entirely inside the latent space of a learned visual world model (a recurrent state-space model, RSSM, identical in spirit to DreamerV2), so the policy sees far more state diversity than offline demonstrations alone provide. It learns multi-task, language-steerable skills from unstructured "play" data — raw teleoperated recordings with fewer than 1% language annotations — by relabeling goals after the fact using images and language (hindsight relabeling). After training purely in simulation inside the world model, the final policy transfers to a real robot arm zero-shot, without any real-world fine-tuning.

Sub-approach: build and use an internal world model to plan — specifically, the world model is used to generate synthetic on-policy rollouts (imagination) so the actor-critic policy trains on a much wider distribution of latent states than the offline dataset contains, directly addressing the covariate-shift problem of behavioral cloning.

The method, in detail

Stage 1 — World model training (scripts/train_wm.py)

A DreamerV2-style world model is trained purely on the offline play dataset. The encoder is a CNN that takes two RGB streams simultaneously — a static overhead camera (rgbs) and a wrist/gripper camera (rgbg) — and outputs a combined embedding, optionally augmented with 15-dimensional proprioceptive state (joint positions/velocities). This embedding feeds into the RSSM, which maintains a recurrent deterministic hidden state ht (GRU cell) and a stochastic categorical latent zt. At each step the RSSM produces a prior distribution over zt from ht alone (the "imagine" path) and a posterior from ht plus the encoder embedding (the "observe" path). The decoder reconstructs both camera images from the concatenation [ht, zt] using transposed convolutions. Training minimizes: (1) MSE image reconstruction loss on both camera views and (2) KL divergence between posterior and prior with a klbalance weighting that blends exact KL on the posterior and on the prior — the same KL-balancing trick from DreamerV2. No language appears in the world model itself; it is purely visual-proprioceptive.

Stage 2 — Policy training in latent space (scripts/train_ag.py)

With the world model frozen (weights not updated), a LUMOS agent (lumos/behavior_models/lumos.py) is trained. The agent has:

  • A plan encoder that embeds a goal — either an image goal or a language instruction — into a compact latent plan vector. Two plan encoders exist: a recognition encoder (uses the full observed trajectory, available during training) and a proposal encoder (uses only start observation + goal, available at test time). This is a variational goal-conditioned architecture similar to SPIRL/Play-LMP.
  • An actor-critic that takes the current RSSM state [ht, zt] plus the plan vector and outputs a continuous action (robot joint delta or end-effector delta) and a value estimate.

Training proceeds by "dreaming" forward: starting from a real transition in the dataset, wm.infer_features() encodes observations into the RSSM posterior, then wm.dream() rolls out purely in latent space for a fixed horizon (no environment interaction, no real images). At each imagined step the actor selects an action, the RSSM prior advances the latent state, and an intrinsic reward is computed as cosine similarity between the current latent state and the target latent (encoded from the goal image). This cosine similarity reward is the only training signal — there is no external simulator, no environment reward. Gradients flow through the imagined trajectory into the actor and critic via the standard Dreamer actor-critic objective (lambda-returns). Covariate shift is mitigated because the policy is trained on the distribution of states it actually visits during imagination, not just on states in the offline dataset.

Hindsight relabeling: To expand the sparse (<1%) language annotations, LUMOS applies image-based hindsight goal relabeling — if a play sequence ends at state s_T, that final state is used as the image goal for all earlier states in the sequence. Language annotations are relabeled similarly: a language instruction is randomly assigned to a trajectory that achieves a matching image goal. This bootstraps language-conditioned training from almost no labeled data.

Inference: At test time, the human gives a language command. The proposal encoder maps (current image, language) to a plan vector. The actor then generates actions step by step using the real robot's camera observations encoded through the frozen world model encoder — the latent state is maintained as a running RSSM posterior, updated at each real timestep. No planning search (no MCTS, no CEM) is used; it is a single forward pass per timestep.

Benchmark: CALVIN (robot manipulation on a tabletop with a Franka arm, 34 language-labeled tasks, evaluated as chains of up to 5 sequential tasks without human reset). LUMOS reports average number of successfully completed tasks in a chain of 5, outperforming MCIL, HULC, and other offline imitation learning baselines. The paper also demonstrates zero-shot transfer to a physical Franka robot.

Run verdict

GPU required; cannot run meaningfully on CPU alone.

  • World model training on CALVIN play data (~300 GB, millions of frames) requires a CUDA GPU with at least 16 GB VRAM (A100 or equivalent is typical for this class of Dreamer model). Training takes hours to days.
  • Agent training in latent space is lighter but still needs GPU for the RSSM forward pass in batch.
  • The CALVIN dataset download itself is the first hard gate: ~300 GB.
  • evaluate_policy.py requires the CALVIN simulation environment (a PyBullet-based setup with a Franka arm) — not just data, but a runnable simulator.
  • On a CPU-only machine: the code will import and the architecture will initialize, but a single training step takes minutes instead of milliseconds; full training is not feasible. There is no pretrained checkpoint in the repo to run inference only, so CPU-only usage is effectively blocked.

LIMT: Language-Informed Multi-Task Visual World Models

ICRA 2025 · 1 citation · sub-approach: build and use an internal world model to plan (model-based RL with imagination rollouts in latent space, multi-task variant conditioned on language)

What it does

LIMT trains a single world model that predicts future states for six robot manipulation tasks at once, conditioning every prediction on a frozen language embedding of the task instruction so the model can exploit semantic overlap between tasks. Instead of running a separate policy in the real environment from scratch, the actor-critic policy is trained almost entirely on imagined rollouts inside the world model's learned latent space, making it far more sample-efficient than model-free multi-task baselines. At test time the robot executes the policy directly in the real (simulated) environment, guided by a natural-language instruction.

Sub-approach: build and use an internal world model to plan — the world model is trained first, then the policy learns entirely through imagination (latent-space rollouts), matching the classical model-based RL / Dreamer family.

The method, in detail

Tokenizer (discrete autoencoder). A VQ-VAE-style encoder with attention blocks maps a 64x64 RGB image plus a 7-D proprioception vector into K=17 discrete tokens (16 image tokens + 1 proprioception token) drawn from a vocabulary of size 512. Training uses cross-entropy token reconstruction, an L2 reward head, binary cross-entropy for episode-end, plus a VGG16-based perceptual loss to keep the image reconstruction visually coherent. This step runs on the offline CALVIN dataset before any RL training begins.

Language conditioning. Task instructions ("open the drawer", etc.) are embedded with Sentence-BERT MiniLM-L6-v2, a small transformer fine-tuned on semantic textual similarity and frozen throughout. The 384-D embedding is concatenated directly to the token sequence fed into both the world model transformer and the actor-critic networks — no cross-attention or FiLM, just concatenation.

World model (GPT-2-style autoregressive transformer). A 10-layer, 4-head, 512-D transformer takes a sliding window of H=8 past time steps, each step containing [observation tokens, language embedding, action], and autoregressively predicts the next observation tokens, scalar reward, and episode-termination flag. This is the heart of the system: it is a next-token predictor over discrete latent states, analogous to a language model predicting the next word, except the "vocabulary" is visual patches of a robot scene.

Policy training via imagination. The actor-critic is trained entirely in the world model's latent space. Starting from a real observation token set, the actor outputs a continuous action; the world model predicts the next token set; this repeats for H=8 steps. The critic uses λ-returns (discount γ=0.65, λ=0.9) with a periodically updated target critic and a small entropy bonus (weight 1e-4) for exploration. No environment interaction is needed during actor-critic gradient updates.

Hybrid data mixing. The world model is first pre-trained offline on the CALVIN dataset. During RL training, 120 short online rollouts (50 steps each) are collected per epoch in the real simulator. An adaptive ratio ponline blends offline filtered data Dfiltered and online data D_online to keep the world model accurate on newly visited states while retaining coverage from offline data.

Multi-task sharing. All six tasks share one tokenizer, one world model transformer, and one actor-critic. Task identity is communicated only through the language embedding — there are no task-specific heads or adapters. During training, data is occasionally relabeled with a different task's instruction (probability 0.15) to force the model to use the language signal rather than memorizing task-specific patterns.

Evaluation. Tested on CALVIN Environment D: a Franka Panda 7-DoF arm in PyBullet, 6 tasks, success measured over 20 rollouts per task. LIMT achieves 52.12% multi-task success vs. 22.99% for a strong model-free baseline (MT-SAC with the same tokenizer + language), a ~2.3x improvement.

Bottom line: GPU + CALVIN simulator + offline dataset required. A CPU-only box could run inference through a trained transformer checkpoint (the computation is not enormous), but training is GPU-mandatory and the code is not available.

X-MOBILITY: End-to-End Generalizable Navigation via World Modeling

ICRA 2025 · 1 citation · Sub-approach: build and use an internal world model to plan (latent imagination rollouts for navigation policy)

What it does

X-MOBILITY trains a robot to navigate cluttered, novel environments by first learning a compressed model of how the world evolves — specifically, how camera images and speed change as it takes actions — and then learning a navigation policy that acts on the outputs of that model rather than raw pixels. The key design insight is that world modeling and action policy are architecturally decoupled, so the model can consume two data streams independently: off-policy data without any expert actions (to learn dynamics) and on-policy demonstration data with expert actions (to learn control). At test time the model deploys zero-shot on a real Nova Carter robot without fine-tuning.

Sub-approach: build + use an internal world model to plan — the RSSM latent state is rolled forward (imagination) during inference to predict future states; the action policy is conditioned on those latent states to choose actions.

The method, in detail

1. Visual encoding.

Each RGB camera frame passes through a frozen pre-trained DINOv2-small (a vision transformer trained with self-supervised distillation) or, optionally, a Depth Anything backbone. The visual feature is concatenated with a learned speed embedding from a 2-layer MLP (SpeedEncoder). The combined vector is 512-dimensional (image backbone hidden_size × 2 + speed channels).

2. Recurrent State Space Model (RSSM).

The RSSM is a standard DreamerV2-style latent dynamics model with:

  • A deterministic path: a single GRU receives the previous hidden state concatenated with a pre-GRU linear projection of the current latent state and action encoding.
  • A stochastic path: two DistributionModel MLPs (2-layer, output 2 × latent_dim, split into mean and log-variance) produce a *prior* (from hidden state + latent action only, no observation) and a *posterior* (additionally conditioned on the current DINOv2 embedding).
  • During training, a dropout switch samples from prior vs. posterior with configurable probability, forcing the prior to stay close to the posterior (regularized with KL divergence).
  • During imagination rollout (inferenceprediction()), the model calls rssm.imaginestep() repeatedly, using only the prior (no new image) to generate future latent states for multiple timesteps ahead.

3. Multi-head decoders.

From the composite state (GRU hidden + stochastic latent sample) several decoder heads are trained simultaneously:

  • StyleGanDecoder (optional): generates semantic segmentation maps and RGB reconstructions at three scales (48×48, 96×96, 192×192 pixels) using adaptive instance normalization on a learnable constant tensor — a lightweight StyleGAN-style upsampler. This is an auxiliary task; it is not used at inference time for navigation, only for representation learning.
  • DepthHead (optional): predicts depth maps using L1 + spatial-gradient loss.
  • ActionPolicy: the main control head.

4. Action policy (the control head).

ActionPolicy first encodes the global route plan (a series of waypoint vectors) through VectorNetSubGraph — a graph neural network that aggregates polyline segments into a single route feature. It then fuses the RSSM latent state with that route feature by concatenation (or optionally MLP-attention or scaled dot-product attention). The fused "policy state" is passed to either:

  • A DiffusionPolicy: a U-Net 1-D denoising diffusion model (DDPM-style) that iteratively denoises from Gaussian noise to produce action + path waypoints.
  • Or an MLPPolicy: two separate tanh-bounded MLP heads for velocity/steering commands and trajectory waypoints.

The diffusion variant is the default and is the one used for the real-robot experiments.

5. Training procedure.

Two training stages are supported:

  • Stage 1 (world model pre-training): only the encoder + RSSM + decoder heads are trained on random-action data (160k rollouts from Isaac Sim). No action policy. Loss = KL divergence (prior vs. posterior) + segmentation cross-entropy + RGB perceptual loss (VGG-16 L1 on feature blocks) + L1 pixel loss + depth loss.
  • Stage 2 (joint training): the action policy is added and the whole model is trained end-to-end on the teacher-policy dataset (100k rollouts with Nav2 expert actions). Loss adds ActionLoss (L1/L2 on velocity commands) + PathLoss (MSE on waypoints) + DiffusionLoss (MSE on predicted noise).

6. Decoupled data training.

Because the world model head and action policy head have separate loss terms, data without action labels contributes only to the world model losses. This is the mechanism enabling off-policy pre-training: the model learns visual dynamics from unannotated driving data and then learns control separately.

7. Deployment and imagination at inference.

At each control step the robot calls inference() once to update the RSSM hidden state from the live camera frame, then optionally calls inferenceprediction() N times using only imaginestep() (no new camera frame) to roll out a predicted future trajectory in latent space. The action policy reads the current latent state and outputs velocity commands and path waypoints. The path is not explicitly used as a cost in a separate optimizer — the policy is a direct regression / diffusion model, not a receding-horizon MPC planner. For sim-to-real, the model is converted to ONNX then TensorRT for real-time inference speed.

Privileged-Dreamer: Explicit Imagination of Privileged Information for Rapid Adaptation of Learned Policies

ICRA 2025 · 0 citations · sub-approach: detect unfamiliar situations & hidden variables (HIP-MDP hidden-parameter estimation inside a world model)

What it does

Robotic controllers degrade when physical parameters they cannot observe — payload mass, surface friction, motor gains — shift between training simulation and real deployment. Privileged-Dreamer frames this as a hidden-parameter Markov decision process (HIP-MDP), where unobservable variables parameterize both the transition function and the reward function, and trains a dual recurrent world model that explicitly estimates those parameters from short observation histories so that the policy can adapt at test time. The sub-approach is detect unfamiliar / hidden variables: the system does not simply absorb distribution shift as extra variance (as domain randomization does); it builds an internal model that guesses what the hidden parameter is and then conditions every downstream network on that guess.

The method, in detail

HIP-MDP formulation. The environment is a tuple (S, A, T(s'|s,a,ω), R(s,a,ω), ρ(ω)) where ω is a hidden vector — e.g. friction coefficient or mass — drawn once per episode from a prior ρ. The agent observes (st, at) but never ω directly.

Base world model — RSSM. Privileged-Dreamer inherits the Recurrent State-Space Model (RSSM) from DreamerV2. The RSSM maintains a recurrent hidden state ht (a GRU cell) and splits the latent representation into a deterministic part ht and a stochastic part zt sampled from a categorical posterior q(zt|ht, xt). The transition prior is p(zt|ht). Image observations are encoded with a CNN encoder; decoded with a CNN decoder. Rewards and episode-continuation (discount) signals are predicted by small MLP heads on (ht, zt).

Dual recurrent architecture — the key addition. A second, independent recurrent module ηϕ is introduced alongside the RSSM. This module is an LSTM that reads the trajectory buffer — specifically the sequence of (observation, action) pairs from the last H=25 steps — and outputs a distribution over the hidden parameter: ω̃t ~ ηϕ(ω̃t | x{t-H:t}, a{t-H:t-1}). The LSTM hidden state is separate from the RSSM GRU state; the two recurrent streams run in parallel.

Privileged information at training time. During training in simulation, the true ω is available (this is the "privileged" information). A second prediction head pϕ(ω̂t | ht, zt) is attached to the RSSM latent and is trained with the true ω as a supervised target. This privileged head teaches the world model's latent to carry information about the hidden parameter. The LSTM estimator ηϕ is simultaneously trained with the same ω target. At test time, ω is unknown, so only the LSTM estimator ηϕ is used — it infers ω̃ purely from recent observations.

Conditioning all downstream networks. The estimated ω̃t is concatenated to ht and z_t before being fed to the actor (policy), the critic (value function), and all world model prediction heads. This means the policy directly receives a belief about hidden parameters when choosing actions.

Loss function. The total objective is:

L(ϕ) = LDreamer + E[ Σt ( −ln ηϕ(ω̃t | x{t-H:t}, a{t-H:t-1}) − ln pϕ(ω̂t | ht, zt) ) ]

where L_Dreamer is the standard RSSM ELBO (reconstruction + KL divergence between posterior z and prior z). The second term is a negative log-likelihood over the hidden-parameter predictions from both the LSTM estimator and the RSSM-latent predictor.

Imagination rollouts for planning. Actor and critic are trained entirely inside the world model's imagination (latent rollouts) — the Dreamer-style "dream" loop. The actor maximizes expected imagined return; the critic regresses imagined values. Because ω̃ is available at each imagined step (propagated through the LSTM), imagined rollouts reflect the current parameter belief, enabling rapid within-episode adaptation.

Benchmark tasks. Five HIP-MDP environments, all MuJoCo-based:

  • DMC Walker Run — hidden: contact friction
  • DMC Pendulum Swingup — hidden: pendulum mass scale
  • Throwing — custom MuJoCo, hidden: ball mass scale
  • Franka Sorting — custom MuJoCo, hidden: object mass scale
  • DMC Pointmass Easy — hidden: motor scales

Baselines: DreamerV2 (no adaptation), PPO (model-free), SAC (model-free), domain randomization, RMA (Rapid Motor Adaptation — teacher-student distillation).

Results. Privileged-Dreamer achieves ~41% higher average reward across all five tasks vs. the next-best baseline, with the largest gains on tasks where the reward itself is parameterized by ω (e.g. Throwing, where throw accuracy depends on ball mass).

Bounding Distributional Shifts in World Modeling through Novelty Detection

IROS 2025 · 0 citations · sub-approach: detect unfamiliar situations & bound hidden-variable uncertainty

What it does

Visual world models break down when a planner proposes action sequences that push the model outside the state-action distribution it was trained on — the model then produces imagined futures that are confidently wrong. This paper (WM-VAE) wraps the DINO-WM world model with a variational autoencoder that acts as a novelty detector: before the robot commits to any action trajectory, every predicted future latent state is passed through the VAE, and states the VAE cannot reconstruct well are flagged as out-of-distribution (OOD). The planner (cross-entropy method) penalises OOD trajectories in its cost, steering optimisation away from unreliable model territory.

Sub-approach: detect unfamiliar situations — the system does not directly imagine future images for a goal, but rather guards the world model's own reliability boundary so that planning stays within the region where predictions can be trusted.

The method, in detail

World model (DINO-WM backbone)

  • An RGB image is passed through a frozen, pretrained DINOv2 vision transformer to produce a patch-level latent state z (a sequence of patch embeddings). DINOv2 is never fine-tuned; only the transition model is learned.
  • The transition model is a Vision Transformer (ViT) that takes the current latent patch sequence zi and an action ai, linearly projects the action into the same token dimension, appends it to each patch, and predicts the next latent state z{i+1}. A dropout layer is inserted before the ViT to improve stability. Formally: z{i+1} = g(z{i-H+1:i}, a{i-H+1:i}; θ), where H is the look-back history window (set to 1 in experiments). The transition model is trained with MSE loss on predicted vs. actual next DINOv2 patch embeddings.

Novelty detector (VAE)

  • A separate VAE is trained on the same latent states z that appear in the training dataset — it learns the distribution of "familiar" latent states. Encoder uses convolutional layers; decoder uses transposed-convolution (deconvolution) layers.
  • The VAE is trained with a standard ELBO: reconstruction MSE plus KL divergence between the approximate posterior and the unit Gaussian prior.
  • At planning time the VAE is frozen. Its role: the reconstruction error MSE(z, VAE(z)) is high for OOD latent states and low for in-distribution ones. No threshold or binary classifier is used; the raw reconstruction loss L_r is the novelty signal.

MPC planning loop (cross-entropy method, CEM)

  • CEM samples K action trajectories of length T from a multivariate Gaussian distribution N(μ, Σ).
  • For each trajectory, the world model autoregressively rolls out predicted latent states z1, …, zT.
  • Each zt is fed to the frozen VAE; reconstruction loss Lr^{z_t} is computed.
  • Total trajectory cost: L = Lg + w · Σt Lr^{zt}, where L_g is the MSE between the predicted final state and the goal state's latent encoding, and w is a scalar weight balancing goal-reaching vs. OOD avoidance.
  • The top-k elite trajectories (lowest cost) update μ and Σ. CEM iterates for a fixed number of rounds; the first action of the best trajectory is executed on the robot.
  • This receding-horizon loop runs at every timestep (model-predictive control, MPC).

Training data and simulators

All data is collected with a random policy in NVIDIA FleX (a GPU-accelerated particle simulator for deformable objects):

  • Granular: 100 trajectories × 20 frames — a robot arm pushing a pile of small particles.
  • Rope: 1000 trajectories × 20 frames — a robot arm pushing a rope.
  • Cloth: 100 trajectories × 5 frames — a robot arm grabbing and placing a cloth square.

DINO-WM is trained separately per environment; the VAE novelty detector is also trained separately per environment on the same latent dataset.

Evaluation metric is Chamfer Distance between the achieved particle/vertex configuration and the goal configuration, averaged over 5 different goal scenes per environment.

Imitation Learning with Limited Actions via Diffusion Planners and Deep Koopman Controllers

ICRA 2025 · 2 citations · Sub-approach: cut labeled-data needs (data-efficient imitation)

Authors: Jianxin Bi, Kelvin Lim, Kaiqi Chen, Yifei Huang, Harold Soh (National University of Singapore, CLeAR lab)

arXiv: https://arxiv.org/abs/2410.07584 · DOI: 10.1109/ICRA55743.2025.11128735

What it does

Most diffusion-based robot policies demand large quantities of paired (observation, action) demonstrations, but action labels are expensive to collect — you need motion capture, teleoperation, or kinesthetic teaching for every frame. KOAP (Koopman Operator with Action Proxy) sidesteps this by treating the bulk of training data as observation-only: it learns a latent representation of "what action must have happened" purely from watching state-to-state transitions, then maps that latent representation to real joint commands with only a small amount of action-labeled data. This is the data-efficient / cut-labeled-data-needs sub-approach to world modeling: the world model here is the Koopman dynamics model, which predicts how observations evolve under actions; the diffusion component plans future observation trajectories; together they replace direct action supervision for most of training.

The method, in detail

Problem setup. You have a large set of expert demonstrations where you recorded robot observations (images or proprioception) but did not record the joint torques or end-effector commands (the actions). You also have a small set of fully labeled demos. The goal is to learn a policy that generalizes across multi-modal behavior (e.g., pick-left vs. pick-right depending on the situation).

Step 1 — Koopman Autoencoder (learning latent dynamics from observations only).

The Koopman Operator is a classical idea from dynamical systems: any nonlinear system can be represented as a *linear* system in a (potentially infinite-dimensional) lifted space. KOAP trains a neural encoder phi that maps each observation ot into a latent vector zt, chosen so that the transition between consecutive latents is *linear*: z{t+1} = A zt + B alatentt, where A (state transition) and B (control matrix) are learned matrices and alatentt is a latent "action proxy." The autoencoder is trained on observation-only sequences by minimizing reconstruction loss (phi^{-1}(zt) ≈ ot) and multi-step prediction loss (how well the linear dynamics roll forward). Crucially, alatentt is inferred from the *difference* z{t+1} - A zt — no action label is needed. This latent action proxy captures what the agent must have done without ever seeing the actual command.

Step 2 — Diffusion Planner (observation-sequence planning).

The planner is a denoising diffusion model conditioned on the current observation and a language or image goal. It does *not* directly output joint actions; it outputs a sequence of future latent states [z{t+1}, z{t+2}, ..., z_{t+H}] (a plan in latent space). Training uses the standard DDPM (Denoising Diffusion Probabilistic Model) objective over the observation-only dataset: learn to denoise a corrupted latent trajectory back to the clean expert trajectory. At inference, the planner draws a noise sample and runs the reverse diffusion chain (typically 50–100 denoising steps) conditioned on the current state and goal, producing a plausible future trajectory.

Step 3 — Linear Action Decoder (bridging latent proxy to real action).

Given the planned next latent state z{t+1} and the current state zt, the latent action proxy is recovered as alatentt = B^+ (z{t+1} - A zt) (pseudo-inverse of B). A linear decoder W then maps alatentt to the real robot action at = W alatent_t + b. This linear decoder is trained on the *small* set of labeled demonstrations via least-squares regression. Because the Koopman space captures rich state-transition structure from the large observation-only corpus, the linear decoder generalizes to new situations despite being trained on very few labeled examples.

Step 4 — Execution at test time.

At each timestep the robot (1) encodes the current observation, (2) runs the diffusion planner to get the next planned latent state, (3) computes the latent action proxy, (4) applies the linear decoder to get the real joint command, and executes it. There are no imagination rollouts in the sense of DreamerV3; the world model is used to structure the latent space so that the planner can reason in it, not for long-horizon policy optimization.

Datasets and tasks. Experiments use the D3IL (Diverse Demonstrations for Imitation Learning) benchmark — a suite of simulated robotic manipulation tasks (block stacking, sorting, pushing) with multi-modal demonstrations. A real-robot experiment with a tabletop arm is also included. The key metric is task success rate as a function of *how many action-labeled demos* are provided (from 0 to ~10% of the full dataset).

RoboEnvision: A Long-Horizon Video Generation Model for Multi-Task Robot Manipulation

IROS 2025 · 0 citations · sub-approach: plan by imagining future images (video-plan)

What it does

RoboEnvision uses a learned video diffusion model as a world model: given a high-level language instruction, it generates a sequence of photorealistic future frames showing the robot completing multiple manipulation sub-tasks, then extracts joint-angle commands from those imagined frames using a lightweight policy network. The key insight is that planning through imagined video sidesteps error accumulation because frames are generated in parallel (keyframe then fill) rather than autoregressively one step at a time. This places it squarely in the "plan by imagining future images" sub-approach: the world model is the planner, and execution follows the imagined trajectory.

The method, in detail

Stage 0 — Task decomposition. A vision-language model (GPT-4o is used at inference time) receives the high-level goal ("pick the red cube, then place it in the bin") and outputs K ordered atomic sub-instructions, one per manipulation primitive.

Stage 1 — Keyframe generation (world model, first diffusion pass). A video Diffusion Transformer (DiT) built on the Open-Sora codebase takes the K sub-instructions and generates exactly K keyframes — one target image per sub-task. The model compresses frames through a VAE (variational autoencoder) into a latent space and denoises from Gaussian noise conditioned on text. A diagonal block-masked cross-attention matrix ensures keyframe i attends only to instruction i, not to instructions for other steps, preventing semantic bleed between tasks. A Semantics-Preserving Attention (SPA) module reinjets the VAE features of the initial observed frame into every spatial attention layer; this anchors object identity (shape, color, position) across large inter-keyframe motions where purely temporal attention would lose track of objects. Full 3D spatio-temporal attention (instead of factored spatial + temporal attention) is used to handle large displacements between keyframes.

Stage 2 — Frame interpolation (filling diffusion model). A second, separate diffusion model takes two consecutive keyframes (the boundary conditions) plus the connecting sub-instruction and generates the dense intermediate frames between them. All K-1 filling passes run in parallel, so the full video is assembled without any autoregressive chaining. Training uses the standard denoising diffusion objective (predict added noise epsilon at each timestep) conditioned on the boundary frames via concatenation in the latent channel dimension.

Stage 3 — Policy model (joint extraction). A transformer-based policy model with spatial-temporal attention blocks plus a ResNet-style decoder processes the full generated video (keyframes and filled frames) and regresses 7-DoF joint angles plus a binary gripper state for each frame. It is trained independently on simulator ground-truth data. At inference time the robot executes the predicted joint sequence open-loop.

Training data. Two datasets: (a) LanguageTable — 50k short-horizon clip sequences concatenated into multi-step videos (360x640); (b) LHMM (Long-Horizon Manipulation in MuJoCo), a new 90k-sequence dataset the authors construct with keyframe annotations derived by detecting grasp/release events (180x320, 3-18 instructions per video). The keyframe diffusion model and the filling model are trained separately on these datasets.

Evaluation. Video quality: LPIPS, SSIM, PSNR, FVD (Frechet Video Distance), CLIP score. Policy quality: task success rate on 45 held-out long-horizon LHMM tasks. Baselines include OpenSora in naive autoregressive, hierarchical autoregressive, and flat modes, plus AVDC (Action Video Diffusion with Control).

Chain-of-Imagination for Reliable Instruction Following in Decision Making

IROS 2025 (Oral) · 0 citations · sub-approach: plan by imagining future images (video-plan)

What it does

Chain-of-Imagination (CoI) is a mechanism that lets an embodied agent break a long-horizon language instruction into a sequence of intermediate visual sub-goals by iteratively using a multimodal large language model (MLLM) paired with a diffusion image-editing model: at each step the system imagines what the world should look like one step from now, then drives a low-level controller toward that imagined frame. The concrete agent built on CoI is called DecisionDreamer; the official implementation and pre-trained weights live in the MineDreamer codebase (IROS '25 Oral, NeurIPS-workshop '24), which is the expanded version of the earlier arXiv release (arXiv:2403.12037) that adds CALVIN manipulation results alongside the original Minecraft evaluation. The sub-approach is "plan by imagining future images": the world model is a learned image-prediction function that produces the next egocentric observation given the current one and a language goal, and the robot acts toward each predicted image in turn.

The method, in detail

The core loop — Chain-of-Imagination (CoI)

At every decision cycle the system does four things in order:

  • Imagine the next visual sub-goal. The *Imaginator* takes the current egocentric observation Ot and the natural-language instruction y and produces a synthetic image I{t+1} showing what the scene should look like one step closer to the goal. This is the world-model prediction: not a reward, not a latent vector, but a full pixel-space image of the next desired state.
  • Convert the imagined image into a latent visual prompt. A small *Prompt Generator* (a conditional variational autoencoder, CVAE) receives the MineCLIP embeddings of the current observation, the imagined image, and the instruction, and outputs a compact latent vector p_t in the same embedding space that the low-level controller expects.
  • Act. The *PolicyNet* (Video PreTraining, VPT, pre-trained on 70 k hours of Minecraft gameplay) receives the current visual features ft concatenated with pt and predicts keyboard-and-mouse actions a_t.
  • Observe and loop. The environment transitions to O_{t+1}, and the cycle restarts from step 1 with the new observation.

The Imaginator in detail

The Imaginator is the world-model component. It is built by connecting LLaVA (a visual-instruction-tuned LLM) to an InstructPix2Pix diffusion U-Net via a *Goal Q-Former*:

  • LLaVA processes the current observation image and the instruction, producing hidden states for a set of learnable [GOAL] tokens.
  • The Goal Q-Former (a cross-attention module with learnable dream-query vectors) compresses those hidden states into a compact feature vector f* that lies in the diffusion model's conditioning space.
  • The diffusion U-Net (InstructPix2Pix backbone, fine-tuned on Minecraft) takes the current observation as the source image and f* as the conditioning signal, then denoises a target image that depicts the desired next state — for example, showing the agent's hand reaching toward a tree when the instruction is "collect wood".

Training is done in three stages:

  • Stage 1 (cross-modal alignment): The Goal Q-Former is trained to align LLaVA's hidden states with CLIP visual features using the CC12M image-caption corpus. LLaVA weights are frozen; only the Q-Former is updated.
  • Stage 2 (diffusion warm-up): InstructPix2Pix is fine-tuned on the *Goal Drift Dataset* — a collection of Minecraft quadruplets (current observation, instruction, next observation, goal description) — while the Q-Former is also frozen. The standard denoising loss is used.
  • Stage 3 (end-to-end fine-tuning): LLaVA is frozen; the Q-Former is updated via LoRA; the diffusion U-Net is updated end-to-end. The joint loss is L = LLLM (cross-entropy on goal-token prediction) + Ldream (noise-prediction MSE from the DDPM objective).

Prompt Generator training

The CVAE Prompt Generator is trained separately on ~10 k Goal Drift quadruplets. Its encoder and decoder are each three-layer MLPs with 512 hidden units. It learns to map (observation embedding, imagined-image embedding, instruction embedding) — all from MineCLIP — to the visual-prompt latent space that VPT's conditioning head expects.

PolicyNet (VPT)

VPT is used as-is (pre-trained weights, no fine-tuning). The visual prompt p_t plugs directly into VPT's existing conditioning interface, so the controller requires no additional gradient updates.

How the robot uses the world model to choose actions

The agent does not do explicit search or rollout-based planning (no model-predictive control, no CEM, no MCTS). Instead CoI is a *reactive imagination loop*: at each timestep the imagined sub-goal is regenerated from the new observation, so the sequence of imagined images adapts online as the environment evolves. This is closest in spirit to goal-conditioned imitation with an iteratively updated goal image.

CALVIN extension (IROS version)

The IROS'25 paper generalises the same CoI mechanism to the CALVIN robot-arm manipulation benchmark. The Imaginator is re-trained on CALVIN trajectories; VPT is replaced with a manipulation-specific low-level policy; the Prompt Generator is adapted to CALVIN's observation space. This lets DecisionDreamer outperform prior generalist agents on CALVIN's chained multi-task evaluation.

SR-AIF: Solving Sparse-Reward Robotic Tasks From Pixels with Active Inference and World Models

ICRA 2025 · 2 citations · sub-approach: plan by imagining future latent states via active inference (expected free energy minimization)

What it does

SR-AIF (Self-Revising Active Inference) trains a robot to solve continuous-action, goal-directed tasks directly from raw pixel images when reward signals are extremely sparse — typically just a single +1 at task completion and 0 everywhere else. The agent builds a learned world model that predicts how the world evolves in a compact latent space, then uses that model to plan actions by minimizing a quantity called expected free energy, which simultaneously drives the robot toward goals and drives it to explore states it does not yet understand. Two novel contributions make this work under sparse reward: a contrastive prior preference learning mechanism that teaches the agent what "success" looks like by learning from a handful of expert demonstrations, and a self-revision schedule that periodically reassigns credit across an episode so the agent can link distant actions to a delayed goal signal.

Sub-approach: plan by imagining futures — the agent runs imagination rollouts inside its learned world model, evaluates those imagined futures under a goal-preference signal, and uses the result to train both a policy (actor) and a value function (critic).

The method, in detail

World model — the RSSM. The core of SR-AIF is a Recurrent State Space Model (RSSM). An RSSM couples a Gated Recurrent Unit (GRU) for temporal memory with a set of stochastic latent variables:

  • *Encoder (approximate posterior):* takes the current pixel observation and the GRU hidden state; outputs a distribution over the current latent state st. Written qθ(st | ot, h_t).
  • *Transition prior:* predicts the next latent state from the current latent and the GRU hidden state alone (no observation), i.e. pθ(st | z_t). This is the "imagination" branch — it lets the agent simulate futures without needing real images.
  • *Decoder (observation likelihood):* reconstructs the pixel image from (st, ht) to keep the latent space grounded in real observations.
  • *Reward predictor:* predicts the reward signal from (st, ht).
  • Latent states use discretized (categorical) distributions rather than continuous Gaussians, following the DreamerV3 recipe. A symlog transform and KL balancing are applied for numerical stability.

The RSSM is trained end-to-end by minimizing the variational free energy (the ELBO): the sum of a reconstruction accuracy term (negative log-likelihood of observations and rewards under the posterior) and a complexity term (KL divergence between the encoder posterior and the transition prior).

Prior preference learning — CRSPP. In standard active inference, the agent needs a "prior preference" distribution — a model of what states it wants to occupy. In sparse-reward tasks this is hard to specify by hand. SR-AIF learns it with a separate, action-free RSSM called the Contrastive Recurrent State Prior Preference (CRSPP) model. This second network watches expert demonstration trajectories (collected by a separately trained PPO agent operating in the fully observable MDP) and learns to produce a preferred-state trajectory ŝ_t.

A self-revision mechanism assigns a credit value ρ_t to each time step: positive (decayed backward from the goal) for successful episodes, negative for failures. The CRSPP is trained with a contrastive objective that pushes the preferred-state distribution to match states from successful episodes and away from failure states. Only positive-credit steps affect the KL term. The similarity between preferred states and world-model states is measured by cosine distance (with stop-gradient on the world model side).

Expected free energy and action selection. The policy (actor) is trained in imagination: the agent unrolls the transition prior for H steps without observations, producing a sequence of imagined latent states. At each imagined step, the expected free energy (EFE) combines four signals:

  • *Epistemic signal A* — policy entropy: encourages diverse action choices.
  • *Epistemic signal B* — information gain about model parameters estimated with a small ensemble, discouraging actions that the model is uncertain about.
  • *Epistemic signal C* — entropy of the generative model's state distribution, pushing the agent toward novel states.
  • *Instrumental signal* — predicted reward plus cosine similarity between the imagined state and the preferred state from CRSPP, pulling the agent toward the goal.

A value function (critic) is trained with a lambda-return target that mixes multi-step returns with bootstrapped value estimates. The actor maximizes the critic's value plus entropy bonuses. Continuous actions are sampled from a Gaussian with tanh normalization; discrete actions use straight-through gradient estimators.

Self-revision schedule. The credit ρ_t is recomputed each episode based on whether the agent succeeded. This backward-decayed credit acts as a curriculum: early in training, failure episodes produce a negative signal that pushes the CRSPP away from those states, while success episodes reinforce good trajectories. The schedule gradually shifts the balance as the agent improves.

Expert data and training flow.

  • Collect 1,000–20,000 steps of expert demonstration data (environment-dependent) from a pre-trained PPO agent that has full state access (MDP setting).
  • Train the CRSPP on the demonstrations to learn preferred state distributions.
  • Train the RSSM world model and actor-critic jointly on environment interaction, using CRSPP-generated preferred states as the instrumental goal signal.
  • Run entirely from pixels (image observations), no privileged state information at deployment.

Environments: Gymnasium Mountain Car (1M steps), Meta-World manipulation suite (13 tasks, 3M steps), and RoboSuite manipulation tasks (5M steps), all with sparse {0,1} rewards.

Curiosity-Driven Imagination: Discovering Plan Operators and Learning Associated Policies for Open-World Adaptation

line: ICRA 2025 · 0 citations · curiosity-driven exploration + symbolic operator discovery via imagination rollouts

What it does

A robot is placed in a manipulation environment and at some point the environment changes in an unforeseen way (a new object appears, a constraint is added). Instead of failing, the system detects the change through curiosity — its neural forward model starts making large prediction errors — and uses that signal to explore, discover what new transitions are now possible, lift those transitions into abstract symbolic planning operators, and then plan in an "imaginary" domain to generate a reward signal that teaches a new low-level policy.

Sub-approach: curiosity-driven exploration — the Intrinsic Curiosity Module (ICM) prediction error is the primary driver; the system also builds and uses an internal world model (the neural transition model) to plan symbolically in imagined space, making it also a build-and-use planner under novelty/uncertainty.

The core claim: you can discover new PDDL-style operators online by observing the robot's own curious exploration, then immediately plan with those operators before a working policy exists.

The method, in detail

1. Low-level neural world model (stochastic transition model)

The agent maintains a neural network τ(s̃{t+1} | s̃t, a_t) that predicts the next continuous state given the current state and a continuous action. State here is *not* pixels — it is joint positions plus object positions and orientations extracted directly from the MuJoCo simulator. The model is trained online via supervised regression on experienced transitions.

2. Intrinsic Curiosity Module (ICM)

The ICM contains two sub-networks trained jointly with the transition model: a forward model (predicts next encoded state from current encoded state + action) and an inverse model (predicts the action that caused a transition, used to learn an action-relevant state encoding). The intrinsic reward is the L2 prediction error of the forward model:

Rintrinsic = || ŝ{t+1} − s̃_{t+1} ||²

Large errors signal novelty — the forward model is surprised because it has not seen this type of transition before. This is the standard Pathak et al. 2017 ICM formulation applied here to robot state space rather than pixels.

3. Symbolic predicate layer (detector)

A hand-designed detector maps continuous states to a set of binary predicates (e.g., "object-held", "object-at-target", "gripper-open"). This is the interface between the continuous neural world and the discrete symbolic planner. Predicate changes between consecutive states define the *effects* of a transition; predicate conditions that held across many transitions leading to the same effect define the *preconditions*.

4. Operator discovery

A lifted operator O = ⟨ψ, ω⟩ has preconditions ψ ⊆ F and effects ω ⊆ F (where F is the predicate set). After curiosity-driven exploration produces a batch of novel transitions, the system mines them for consistent predicate patterns and proposes a new operator. This is essentially rule induction over observed (pre-state, post-state) predicate pairs.

5. Imaginary domain planning

The system maintains an imaginary PDDL domain σim = ⟨E, F, Sim, O_im⟩ that includes operators the agent has *not yet learned a policy for*. A classical planner (Metric-FF or a hierarchical HDDL planner, lilotane) runs over this imaginary domain to produce a symbolic plan. The plan is converted into a reward machine: a finite automaton whose states correspond to plan steps and whose transitions emit dense reward signals based on whether the relevant predicate just became true. This is the key trick: planning in imagination produces a dense reward shaping signal before the robot has actually mastered the task.

6. Reward machine execution

The reward at each step is:

r(st, s{t+1}) = R_m if the reward machine's current LTL subgoal is satisfied

R_intrinsic otherwise

So the robot pursues symbolic subgoals (reward machine) while falling back to curiosity when it is lost. Each sub-operator (pick, reach, drop) is treated as a separate policy trained with Hindsight Experience Replay (HER) over a goal-conditioned reward.

7. Novelty injection evaluation

The benchmark is RoboSuite Pick-and-Place-Can (a MuJoCo continuous control task) with *sequential novelty injections* — after the agent has learned a base task, the environment is modified (e.g., adding a new object that must be moved first). The agent must detect the novelty via rising ICM error, explore, discover new operators, replan, and learn new sub-policies — all without a reset or human labels.

What the repo is / how you'd run it

LUMOS is a two-stage offline-to-on-policy imitation learning pipeline for long-horizon robot manipulation. Stage 1 trains a DreamerV2-style world model on play data (no language needed). Architecture — module map

World model (lumos/world_models/)

| Component | Class | File |

|---|---|---|

| Abstract base | WorldModel | world_model.py |

| Concrete WM | DreamerV2(WorldModel) | dreamer_v2.py |

The RSSM (Recurrent State Space Model) is the core of the world model. Its state at every timestep has two parts:

  • h — deterministic hidden state, size deter_dim=1024, evolved by a stacked GRU.
  • z — stochastic latent, shaped (stochdim=32, stochrank=32) = 1024 dims, sampled from a categorical distribution (straight-through estimator). The feature vector fed to the decoder and policy is the concatenation [h, z], total 2048 dims.

Behavior / policy model (lumos/behavior_models/)

| Component | Class | File |

|---|---|---|

| Top-level agent | LUMOS(pl.LightningModule) | lumos.py |

| Perceptual adapter | CodeNetwork | perceptualencoders/codeencoder.py |

| Language goal | LanguageGoalEncoder | encoders/goal_encoders.py |

| Visual goal | VisualGoalEncoder | encoders/goal_encoders.py |

| Plan prior (proposal) | PlanProposalNetwork | planencoders/planproposal_net.py |

| Plan posterior (recognition) | PlanRecognitionBiRNNNetwork or PlanRecognitionTransformersNetwork | planencoders/planrecognition_net.py |

| Action decoder | GaussianDecoder(ActionDecoder) | decoders/gaussian_decoder.py |

| Critic (value fn) | Critic | actor_critic/critic.py |

| Aux loss network | projvislang | auxiliarylossnetworks/projvislang.py |

The plan is a learned latent variable (plan_features dims, discrete categorical in the default config) that summarises the intention for a sequence. A plan proposal net produces a prior (at inference, conditioned only on the first observation + language goal); a plan recognition net produces a posterior (conditioned on the full sequence). Their KL divergence is a training loss term.

DreamerV2.dream() (dreamer_v2.py, line 145):

This calls RSSMCell.forward() without an embed argument, so the cell falls back to the prior branch: the next latent state is predicted entirely from (h, z, action) — no real image is consulted. This is the imagination.

  • Intrinsic reward in latent space.

The reward at step k is the cosine similarity (normalised by max-norm) between the imagined next h component and the cached ground-truth h for that timestep:

(maxcos in utils/rlutils.py, line 52). The policy is rewarded for steering imagined trajectories toward latents that match real data.

  • Lambda-return and actor-critic update.

lambdareturn() (utils/rlutils.py, line 4) computes generalised advantage estimates. LUMOS.loss() assembles five terms:

- loss_critic = 0.5 * MSE(values, returns.detach())

- lossactor = actoralpha * (-returns[:-1]).mean() (dynamics backprop through the WM)

- loss_entropy = -eta * entropy.mean() (disabled in default config, eta=0)

- losskl = klbeta * (alpha * KL(pr||pp.detach()) + (1-alpha) * KL(pr.detach()||pp)) (KL balancing)

- lossbc = bcalpha * MSE(imaginedactions, gtactions) (off by default)

Additionally, a CLIP-style contrastive auxiliary loss (clipauxiliaryloss(), line 554) aligns the sequence visual embedding with the language embedding using an InfoNCE objective.

Two separate optimisers are stepped manually (automaticoptimization = False): actoroptimizer over the decoder + perceptual + goal + plan networks; critic_optimizer over the critic alone.

X-MOBILITY — code walkthrough

What the repo is / how you'd run it

X-MOBILITY is NVIDIA's end-to-end navigation system for wheeled robots. It trains a generative world model on robot trajectories recorded in Isaac Sim, then deploys the resulting policy over ROS 2 on real hardware (a Carter robot). The world model learns to predict future camera observations and semantic segmentation given actions, and the policy head reads out of that learned latent space.

Training entry point — train.py::main():

  • argparser.py::parsearguments(TaskMode.TRAIN) collects --config-files, --dataset-path, --output-dir, and an optional --checkpoint-path.
  • One or more .gin files are parsed (gin.parseconfigfile). All hyperparameters — RSSM dimensions, loss weights, encoder choice, sequence length — live in the gin files; the Python code has no hard-coded numbers.
  • train() (gin-configurable) creates a XMobilityIsaacSimDataModule (or XMobilityLeRobotDataModule), wraps it with a pytorch-lightning Trainer using DDP, and calls trainer.fit.
  • Checkpoints go to output_dir/checkpoints/; Weights & Biases is used for logging.

Evaluation entry point — evaluate.py::main():

  • --evaltarget observation runs evaluateobservation(): standard Lightning .test() on the held-out split, computing IOU and action metrics.
  • --evaltarget imagination runs evaluateprediction() via PredictionEvaulator in model/eval/predictionevaluator.py. Given maxhistorylength real frames, it rolls the world model forward for up to maxfuture_length steps using only predicted actions (no real observations), then compares predicted semantics/RGB against ground truth.

Simulation — data must come from NVIDIA Isaac Sim. The dataset loader (model/dataset/isaacsimdataset.py) reads Parquet-based trajectory files that include cameraimage, egospeed, drivingcommand, path, and routeposes columns. Isaac Sim provides photorealistic renders, semantic labels, and the vehicle's odometry. A LeRobot adapter (lerobot_dataset.py) can load community robot datasets in a compatible format.

Deployment — after ONNX or TensorRT conversion (onnxconversion.py, trtconversion.py), the model runs as a ROS 2 node in ros2deployment/xmobility_navigator/.

The RSSM, step by step

The RSSM is the heart of the system. Every timestep it maintains two tensors:

  • h_t — a 1024-d deterministic hidden state (the GRU's hidden vector). This is the "memory" that persists across time.
  • sample_t — a 512-d stochastic latent sample drawn from either the posterior (training) or prior (imagination). This is the "uncertainty" representation.

The policy and decoders read cat([ht, samplet]), a 1536-d vector.

Outer loop — RSSM.forward() (rssm.py lines 138–174)


for t in range(sequence_length):
    action_t = zeros if t == 0 else action[:, t-1]
    output_t = self.observe_step(h_t.detach(), sample_t.detach(),
                                 action_t, input_embedding[:, t], ...)
    use_prior = self.training and self.use_dropout and rand < dropout_probability and t > 0
    sample_t = output_t['prior']['sample'] if use_prior else output_t['posterior']['sample']
    h_t = output_t['posterior']['hidden_state']

The loop iterates over sequence positions (default length 4). At each step it calls observestep, which runs both the prior and posterior branches. The usedropout flag (off by default) is a "dreaming" regulariser: it occasionally feeds the prior sample back instead of the posterior, forcing the prior to stay close to the posterior without direct observation.

observe_step() — the combined prior + posterior step (lines 176–202)


def observe_step(self, h_t, sample_t, action_t, embedding_t, use_sample=True):
    prior_output = self.imagine_step(h_t, sample_t, action_t, use_sample)

    latent_action_t = self.posterior_action_module(action_t)
    posterior_mu_t, posterior_sigma_t = self.posterior(
        torch.cat([prior_output['hidden_state'], embedding_t, latent_action_t], dim=-1))

    sample_t = self.sample_from_distribution(posterior_mu_t, posterior_sigma_t, use_sample)
    posterior_output = {
        'hidden_state': prior_output['hidden_state'],
        'sample': sample_t,
        'mu': posterior_mu_t, 'sigma': posterior_sigma_t,
    }
    return {'prior': prior_output, 'posterior': posterior_output}

The posterior sees all three signals — the recurrent hidden state (past dynamics), the current observation embedding (present sensory data), and the action. This is the inference network: it "corrects" the prior by conditioning on what was actually observed.

imagine_step() — pure prior / rollout step (lines 204–226)


def imagine_step(self, h_t, sample_t, action_t, use_sample=True):
    # Deterministic recurrent update
    input_t = self.pre_gru_net(sample_t)              # 512 → 1024
    _, h_t = self.recurrent_model(input_t.unsqueeze(1), h_t.unsqueeze(0))

    sample_t = self.sample_from_distribution(prior_mu_t, prior_sigma_t, use_sample)

A two-layer MLP that outputs 2 * state_dim values, split into a mean and a log-sigma. The sigmoid squashing keeps sigma in a numerically stable range.

samplefromdistribution() — reparameterisation (lines 228–234)


@staticmethod
def sample_from_distribution(mu, sigma, use_sample):
    sample = mu
    if use_sample:
        noise = torch.randn_like(sample)
        sample = sample + sigma * noise
    return sample

Standard reparameterisation trick: gradients flow through mu and sigma; the stochastic node noise is treated as a constant. At inference (use_sample=False), returns the mean only, giving deterministic predictions.

Where the core idea lives — the recurrent latent dynamics (prior vs posterior)

The RSSM's conceptual split between prior and posterior is the central mechanism of the paper. Both live in model/x_mobility/rssm.py.

Prior (imagine_step, lines 204–226): the model's prediction of what the world will look like given only past state and the commanded action. At deployment there is no real observation to condition on, so the model "imagines" forward using only the prior. This is how it generalises — it has an internal model of navigation dynamics that it can unroll without sensor input.

Posterior (observe_step, lines 176–202): trained by conditioning on the actual observation embedding. During training, the posterior has access to the ground-truth frame and must squeeze all useful signal about the current state into the 512-d stochastic latent. The KL loss then pushes the prior to be as close as possible to that posterior without seeing the observation.

The defining lines are the two DistributionModel calls in observe_step:


# Prior branch (no observation)
prior_output = self.imagine_step(h_t, sample_t, action_t, use_sample)

# Posterior branch (conditions on embedding_t from the real camera frame)
posterior_mu_t, posterior_sigma_t = self.posterior(
    torch.cat([prior_output['hidden_state'], embedding_t, latent_action_t], dim=-1))

The posterior shares prioroutput['hiddenstate'] — so both branches read the same GRU state, but only the posterior also reads embeddingt. At deployment you simply never call the posterior branch; you call imaginestep directly in a chain.

The KL loss is in model/loss/losses.py::KLLoss.forward() (lines 263–271):


prior_loss = self.loss(prior_mu, prior_sigma, posterior_mu.detach(), posterior_sigma.detach())
posterior_loss = self.loss(prior_mu.detach(), prior_sigma.detach(), posterior_mu, posterior_sigma)
return self.alpha * prior_loss + (1 - self.alpha) * posterior_loss

alpha=0.75 means the prior is pushed harder toward the posterior than the posterior is toward the prior. Both gradients are gated by .detach() so each branch only receives the gradient from its own direction of the KL. The KL weight in training is 0.001 — deliberately tiny relative to action loss (10.0) and semantic loss (2.0), so reconstruction quality dominates.

What you'd need to run it

Minimum requirements:

  • Python 3.10+, PyTorch 2.x with CUDA. The model uses 16-mixed precision (bf16 or fp16). A single A100 or comparable data-centre GPU is realistic for training; a T4 could work for single-GPU fine-tuning with batch_size=1.
  • transformers==4.48.1 for DINOv2 and DepthAnything; diffusers==0.29.2 for the RGB and policy diffusion models. pytorch-lightning==2.5, gin-config, wandb.
  • Training data requires Isaac Sim. The dataset loader (isaacsimdataset.py) expects Parquet trajectory files produced by a specific Isaac Sim collection pipeline. There is no bundled dataset and no public download link in the repo. Without Isaac Sim you cannot create new training data; you can only load an existing checkpoint and run inference.
  • The alternative lerobot_dataset.py loader can ingest LeRobot-format community datasets (e.g. collected on real hardware), though the semantic label mapping differs.

CPU-only verdict: not viable for training. The DINOv2 and DepthAnything backbones are large vision transformers, and the diffusion decoders require many forward passes per sample. requirements.txt lists tensorrt==8.6.1, which is GPU-only and not optional for production inference. For offline analysis or debugging individual modules (e.g. stepping through rssm.py logic with random tensors) a CPU will work, but expect 100x+ slowdown.

ROS 2 deployment: requires ROS 2 Humble or later plus the Nav2 stack. The ros2deployment/ directory contains a ready-made package. After TensorRT conversion (trtconversion.py), the model runs on Jetson or a workstation with an NVIDIA GPU.
