Foundation models as robot planners: the web's knowledge meets physical action

A robot trained only on demonstrations knows only what it has seen. Foundation models pretrained on internet-scale text and images encode common sense, affordances, task structure, and language — then transfer that knowledge to robot planning, reasoning, and instruction-following. 01 · the problem

Why robots need the web's knowledge

Collecting robot demonstrations is expensive: you need a physical robot, a human operator, and hours of recording time per skill. A policy trained on 100 demonstrations has never heard of objects it wasn’t shown, instructions it wasn’t given, or situations it hasn’t seen. It is brittle in exactly the ways that matter outside the lab.

The insight that drives the field is that this knowledge already exists — encoded in the weights of large language and vision models pretrained on text, images, and video from the internet. Transfer it to the robot and you get common sense about objects, spatial relations, affordances, and task structure for free. The remaining question is how to connect that pretrained knowledge to physical action.

the actual math — one level deeper

Pre-training objective (next-token): L = -E[log pθ(xᵗ | x₁..xᵗ₋₁)] minimized over trillions of tokens.

Transfer: p(y | x, task) = pθ(y | x, prompt) where only the prompt (or a thin LoRA adapter ΔW) changes between tasks.

02 · the engine

Predict the missing piece, at internet scale

The training signal is automatic: take a sentence, hide a word, ask the model to predict it. Do this billions of times over the entire web and the model must learn grammar, facts, spatial relations, and causality — because those are what make predictions correct. No engineer labels any of it. The data is its own supervision.

The same idea scales to images (mask patches, predict them) and to image-text pairs (align the representations). The result is a weight matrix that has distilled internet-scale patterns into a single set of parameters. That is what “pretrained” means: before the robot ever appears, the model already knows a great deal about how the world looks and works.

the actual math — one level deeper

Masked prediction: L = -E[log pθ(xᵎ | x\xᵎ)] — predict the masked token from the rest; no human labels needed.

Contrastive alignment (CLIP): L = -log(exp(sim(v,t)/τ) / Σᵉ exp(sim(v,tᵉ)/τ)) — image-text similarity, normalized over a batch.

03 · reuse it

One backbone, many robot jobs

Fine-tuning rewrites a small fraction of the model’s weights — sometimes as few as 0.1% via LoRA — on task-specific examples. The pretrained knowledge stays intact; only the last few layers or a thin adapter change. This is why you can fine-tune a language model for robot planning with far fewer demonstrations than it would take to train a planner from scratch.

Prompting skips even the weight update: you describe the task in language, give a few examples, and let the frozen model reason. Code-as-Policies works this way — the robot describes its sensors and available primitives in the prompt, asks the LLM to write a control loop, and runs that code. The backbone was never designed for robotics; prompting is the bridge.

the actual math — one level deeper

LoRA: freeze W, learn ΔW = AB where rank(A,B) ≪ rank(W). Trainable params: r(dᵢₙ + dᵢᵘᵗ), e.g. 0.1% of total.

In-context conditioning: p(aᵗ | o, demos) = pθ(aᵗ | concat[demo₁..demoᵏ, o]) — no gradient update; adaptation is pure inference.

04 · the mechanism

Language as the planning language

Planning with an LLM works because the LLM has already read millions of how-to guides, recipes, and instructional texts. It knows that making coffee involves finding a mug, placing it under the spout, and pressing the button — not because it was trained on coffee-robot data, but because it was trained on language about coffee. That prior drives zero-shot task decomposition.

The output can be a list of steps, a Python function, or a behavior tree node — each is a different grounding format. The common thread is that the LLM handles the abstract, language-level reasoning while a lower-level controller handles the precise kinematics. The abstraction gap between “pick up the mug” and the exact joint angles is bridged by a skill library or motion planner beneath the LLM.

the actual math — one level deeper

Task decomposition: p(stepᵗ | goal, step₁..stepᵗ₋₁) = LLMθ(stepᵗ) — each subgoal sampled autoregressively from the goal and prior steps.

Grounding: skillᵗ = π₂(stepᵗ, obs) where π₂ is a low-level motor policy; the LLM generates steps, the skill library executes them.

05 · the catch

Hallucination and the geometry gap

The failure mode is hallucination: the model predicts the most statistically likely next token, not the physically correct one. It will confidently state that the knob is on the left when it is on the right, or plan a grasp at a point that is not on the object’s surface. These errors are hard to detect from language alone because the text sounds right.

The practical response is grounding: anchor the LLM’s predictions to actual 3D perception, ask a verifier to check the plan before execution, or provide the model with proprioceptive feedback that corrects its assumptions. Retrieval-augmented methods go further — instead of relying on the model’s memory, they look up the relevant facts at query time. Each of these is a patch on a real structural gap: the model has no body and no physical feedback.

the actual math — one level deeper

Hallucination rate: P(wrong | text-plausible) ≫ 0 because pθ(token) is a linguistic prior, not a physical-world prior.

Grounding fix: inject retrieval R(q) or a verifier v(plan, obs) ∈ {0,1} before execution; reject plans where v=0.

Part II

The benefits people actually get

Every family below leans on one or more of these — the recurring reasons to put a foundation model at the center of a robot system rather than a task-specific trained policy.

Zero-shot task generalization

Because the model was pretrained on internet-scale text and images, it can follow instructions about tasks it was never explicitly trained on. The knowledge of what a task requires is already in the weights.

No labels needed for pretraining

Self-supervised objectives (next-token prediction, masked image modeling) use the data as its own supervision. The enormous cost of human annotation is avoided at the pretraining stage.

Composable planning at any granularity

Language is the planning language: the model can produce a one-sentence plan, a five-step list, a Python function, or a full behavior tree — any of which can be passed to a lower-level executor.

Rapid adaptation with tiny fine-tunes

LoRA and prompt-tuning let a robot adapt a general foundation model to a new skill or domain with a fraction of the compute it would take to train from scratch. The pretrained knowledge does most of the work.

Interpretable, debuggable reasoning

Language-level plans are readable by a human, which makes it possible to audit what the robot intends to do before it acts. This is harder to achieve with end-to-end black-box policies.

LLM behavior-tree & symbolic planning

robotics
the problem

Classical planners require manually specified domain models (PDDL predicates, operators) that cannot generalize beyond what engineers wrote. Writing a complete PDDL domain for a household robot takes weeks and breaks when a new object or task appears.

the approaches

Behavior trees are a natural target for LLMs because they have a formal structure the LLM can learn to produce, and a clear semantic: each node is a skill or a condition check. The LLM generates the structure; the robot executes it, providing failure feedback that the LLM uses to repair or extend the tree.

The feedback loop is the key contribution across this family: the LLM does not plan once and forget. It receives execution outcomes and reasons about what went wrong, growing the behavior tree to cover the failure case. This is iterative model building, not one-shot planning.

worked example — one concrete run
  1. User says: 'Make a tea and bring it to the office'. No PDDL domain exists for this.
  2. LLM receives the goal + a list of available robot skills (pick, place, press, navigate). It generates a behavior tree as JSON: sequence[find_kettle, fill, boil, find_mug, pour, navigate_office, place].
  3. A syntax checker validates the BT structure — if a node is undefined, it signals the LLM for a reflective correction pass.
  4. The BT runs; at step 3 (boil) the robot detects failure (kettle not found). LLM expands the BT with a new subtree: find_kettle_alternative → fetch_from_cabinet.
  5. Final success rate on novel household tasks: 72% (LLM-BT) vs 31% (hand-coded BT) on unseen object layouts.
  • ROBO
    LLM-as-BT-Planner: Leveraging LLMs for Behavior Tree Generation in Robot Task Planning — in-context learning and fine-tuning of smaller LLMs to generate syntactically valid BTs from task descriptions

    Classical planners need hand-written domain models (PDDL) that break when new objects or tasks appear. This work asks: can smaller LLMs generate behavior tree structures on the fly from task descriptions? The approach fine-tunes on pairs of task prompts and valid BT outputs to teach syntactic correctness. Success means the LLM can produce execution-ready trees without a human domain engineer.

    how it actually works

    The mechanism: The LLM is trained on (task description, valid BT JSON) pairs. At test time, given a task like 'make coffee,' the model predicts a behavior tree node by node. Each node names a skill or a condition check, and a static checker runs over the output to catch undefined nodes.

    If a node is undefined, the LLM gets feedback and can regenerate that portion. Because the training data is carefully curated, the model learns to emit syntactically valid structures that a real robot executor can parse and run.

  • ROBO
    HBTP: Heuristic Behavior Tree Planning with Large Language Model Reasoning — LLM generates heuristic paths over action space to guide BT expansion; reflective feedback corrects errors

    Generating a single behavior tree is not enough — the robot needs to adapt when the world does not match the plan. This work adds heuristic reasoning: the LLM generates action paths that guide which parts of the behavior tree to expand next. A reflective feedback loop lets the LLM see what failed and propose a fix.

    how it actually works

    The mechanism: The LLM generates a heuristic ordering over the action space — which steps are most promising given the current state and goal. This heuristic becomes the priority queue for behavior tree expansion. When a node fails, the robot captures the failure trace and feeds it back to the LLM.

    The LLM then reasons about why the failure happened and generates a corrective or expanded subtree to replace the failed node. This creates an iterative refinement loop where LLM reasoning and execution feedback tightly couple.

  • ROBO
    Automatic Behavior Tree Expansion with LLMs for Robotic Manipulation — LLM diagnoses execution failures and dynamically expands behavior tree nodes at runtime

    Static behavior trees written offline fail at the first deviation — the robot needs to diagnose what went wrong and grow new branches to handle it. This work gives the LLM read access to the robot's execution trace: it sees which step failed, what the sensor data showed, and can propose a new subtree on the spot.

    how it actually works

    The mechanism: At runtime, the LLM monitors the behavior tree execution. When a node fails (e.g., 'grasp_object' returns False), the robot sends the failure event to the LLM together with the current state snapshot. The LLM diagnoses the failure and proposes a replacement subtree. The new subtree is grafted into the tree and execution resumes.

    Key: this happens at runtime, not during offline planning. The LLM acts as an online repairer, growing the tree to cover cases that offline planning did not foresee.

  • ROBO
    CLIMB: Language-Guided Continual Learning for Task Planning with Iterative Model Building — LLM bootstraps PDDL domain models from natural language and iteratively refines predicates from execution feedback

    PDDL domains are hard to hand-write and brittle to change. This work reverses the process: the LLM reads natural language task descriptions and bootstraps PDDL predicates and operators automatically. As the robot executes and fails, the LLM refines the predicates based on what failed.

    how it actually works

    The mechanism: Step 1: LLM reads a natural language task specification and generates an initial PDDL domain (predicates, operators, constraints). Step 2: The domain is compiled to a planner (like FD or PDDL-Planner), which generates a plan for the current state. Step 3: The robot executes the plan and reports success or failure.

    If a plan failed, the LLM examines the failure and refines the PDDL predicates — e.g., 'add a predicate is_fragile(obj)' or 'refine the precondition on pour.' This iterative model building gradually converges to a working domain.

Language-grounded scene understanding

both
the problem

A robot needs to identify objects it has never seen before, locate them in 3D, and understand their spatial relationships — without a pre-built object database. Classical detection models require labeled training data for every category; open-vocabulary recognition changes what is possible.

the approaches

Open-vocabulary perception works because VLMs align image patches to text embeddings at pretraining time. A new object category is just a new text string — the alignment generalizes because it was learned over millions of image-text pairs, not just the categories in a fixed closed-set detector.

The practical pattern is to maintain a persistent semantic map: as the robot moves, VLM features are projected into a 3D grid and matched to language queries on demand. Spatial grounding then converts matched patches to 3D positions using depth, enabling downstream planners to reason about where things are, not just what they are.

worked example — one concrete run
  1. Camera image shows a kitchen: fridge, mug, and a novel 'AeroPress' coffee device never seen in training.
  2. VLM encodes the image and the query text 'where is the AeroPress?' into a joint embedding space.
  3. Open-vocabulary semantic map: patch features matched to text embedding, top-3 patches voted → bounding box [320px, 180px, 410px, 270px].
  4. Depth sensor fuses the 2D box to 3D: object centroid at [0.4m, 0.1m, 1.2m] in robot frame.
  5. Language query 'bring the AeroPress to the table' routes to the motion planner with that 3D pose — zero labeled examples of AeroPress used.
  • ROBO
    One Map to Find Them All: Real-time Open-Vocabulary Mapping for Zero-shot Multi-Object Navigation — VLM embeddings build persistent open-vocabulary semantic maps; uncertainty drives exploration

    Classical object detectors work only on categories seen in training data — a robot searching for an unfamiliar object is lost. Open-vocabulary perception uses VLM embeddings to match image patches to text descriptions of unseen objects. The approach builds a persistent semantic map: as the robot moves, VLM features are fused into a 3D grid.

    how it actually works

    The mechanism: At each timestep, the robot captures an RGB-D image. A VLM encodes the image and text queries ('where is the AeroPress?') into a shared embedding space. Patches matching the query text are voted by geometric consistency, producing a bounding box.

    Depth fills the 2D box to 3D coordinates. These coordinates are added to a persistent map grid, tagged with the VLM feature. On future queries, the robot looks up similar features in the map and returns the 3D position without re-processing the image. Uncertainty drives exploration: regions with high query-feature variance are prioritized.

  • ROBO
    SpatialBot: Precise Spatial Understanding with Vision Language Models — fine-tune VLM on RGB-D inputs with depth-aware QA datasets for 3D spatial reasoning

    Standard VLMs trained on web data rarely see RGB-D inputs and cannot reason about 3D spatial relationships — depth is treated as an alien modality. This work fine-tunes a VLM on RGB-D question-answering pairs, teaching it to fuse depth and color to answer spatial questions like 'is the mug to the left of the plate?'

    how it actually works

    The mechanism: A pretrained VLM encoder processes both RGB and depth images. For each image, a depth-aware QA dataset provides pairs like (RGB-D image, 'describe the spatial arrangement', answer text). The VLM is fine-tuned to predict the answer given the question and both modalities.

    During training, depth tokens are added alongside RGB patch tokens, and the model learns cross-modal alignment. At test time, the model can answer 3D spatial queries (e.g., 'where is the object relative to the table?') by reasoning over both color and depth.

  • ROBO
    3D Spatial Understanding in MLLMs: Disambiguation and Evaluation — fine-tunes MLLMs with 3D-aware representations for precise object localization and spatial grounding

    Multimodal models struggle with precise 3D object localization because their pretraining emphasizes semantic understanding over metric accuracy. This work fine-tunes multimodal models on 3D-aware datasets with coordinate labels and spatial reasoning questions, teaching them to output precise 3D positions.

    how it actually works

    The mechanism: The MLLM is given RGB-D images paired with 3D annotations (object bounding boxes in camera coordinates). Fine-tuning targets include visual question answering about spatial relationships and coordinate prediction tasks. The model learns to attend to depth cues and correlate them with 2D visual features.

    Key: explicit 3D supervision during fine-tuning — the model is penalized not just for wrong semantic labels but for wrong coordinates. This forces the model to learn depth reasoning, not just language-level object identification.

  • CVPR
    The Power of Prior: Training-Free Open-Vocabulary Semantic Segmentation — frozen MLLM features enable zero-shot dense prediction without any task-specific training

    Dense semantic segmentation usually requires pixel-level labels for every new task. This work shows that frozen MLLM features (without any task-specific training) can enable zero-shot segmentation. The frozen model's internal representations already capture semantic structure; the challenge is extracting it without fine-tuning.

    how it actually works

    The mechanism: A frozen MLLM encodes the image into per-patch embeddings and text embeddings from class names. Cosine similarity between patch embeddings and class embeddings produces a dense prediction map. No backprop, no labeled training data — just similarity matching in the frozen feature space.

    Why it works: The MLLM's pretraining has already aligned image patches to text descriptors (e.g., 'chair' patches cluster near 'chair' text). At test time, querying similarity to class names extracts this structure as a segmentation.

In-context learning & prompting

both
the problem

Fine-tuning a model for each new robot task is expensive and slow. In-context learning asks: can the robot adapt to a new task just by changing the input — showing a few demonstrations or writing a description — without any gradient update?

the approaches

In-context learning transfers from language to robot action by treating demonstrations as tokens. Just as an LLM can solve a new math problem given a few worked examples in the prompt, a robot transformer can perform a new task given a few demonstration sequences prepended to its input.

The limit is context length: three demonstrations fit; thirty become impractical. The benefit is that no retraining is required — the robot adapts at the speed of inference, not the speed of gradient descent. This is the fastest possible adaptation loop.

worked example — one concrete run
  1. New task: fold a shirt. The robot has 3 video demonstrations of a human folding.
  2. Demonstrations are encoded as sensorimotor token sequences: [obs₁, act₁, obs₂, act₂, ...] — each frame + action pair becomes 196 + 7 tokens.
  3. All 3 demos concatenated = 603 context tokens prepended to the current observation.
  4. The causal transformer (ICRT) predicts the next action token autoregressively — no weight update, just inference.
  5. Success on the unseen shirt style: 68% (3-shot in-context) vs 12% (zero-shot) — the demonstrations are the adaptation signal.
  • ROBO
    ICRT: In-Context Imitation Learning via Next-Token Prediction — causal transformer performs next-token prediction over sensorimotor trajectories; test-time adaptation via prompting

    Fine-tuning a robot policy for a new task takes hours or days — the robot cannot adapt at demonstration time. In-context learning asks: can a transformer predict the next action token given a few prior (observation, action) sequences concatenated as tokens? No weight update, just inference.

    how it actually works

    The mechanism: Each demonstration is tokenized: RGB patches, action vectors, and proprioceptive state become sequences of tokens. Three demos (observation-action-observation-action...) are concatenated to form the input context. A causal transformer attends to this context and predicts the next action token autoregressively.

    Training: The model is trained on next-token prediction loss over trajectory data, just like language model pretraining. Test time: Prepend a few in-context demos and let the transformer roll out the next action tokens. Adaptation is pure inference — no retraining required.

  • ROBO
    SAS-Prompt: Large Language Models as Numerical Optimizers for Robot Self-Improvement — structured prompt (Summarize-Analyze-Synthesize) iterates over execution traces for gradient-free policy optimization

    Gradient-based learning requires differentiable simulators and careful reward design — impractical for complex robot tasks. This work uses structured prompting to ask an LLM to optimize robot controllers. The prompt follows a Summarize-Analyze-Synthesize pattern over execution traces.

    how it actually works

    The mechanism: The LLM receives traces of robot rollouts: observations, actions, and rewards. The Summarize step extracts key patterns ('the robot knocked over the object'). Analyze identifies the cause ('grasp was too weak'). Synthesize proposes a parameter update ('increase gripper force by 10%').

    The LLM predicts the new parameters as code or text. The robot executes with updated parameters and reports the outcome. No gradients, no autodiff — the LLM acts as a symbolic optimizer, reasoning about failure modes and proposing fixes in language.

  • ROBO
    LEMMo-Plan: LLM-Enhanced Learning from Multi-Modal Demonstration for Planning Sequential Contact-Rich Manipulation Tasks — in-context prompting integrates tactile and force-torque signals from demos; LLM generates task plans for new configurations

    Most demonstrations only show vision and joint positions — they omit tactile and force-torque signals that are critical for contact-rich manipulation. This work shows that in-context prompting can integrate multi-modal demonstration signals. The LLM reads text encodings of tactile/force traces and generates task plans that account for contact.

    how it actually works

    The mechanism: Demonstrations are encoded as multi-modal sequences: RGB frames, joint positions, tactile readings (pressure map), and force-torque vectors. These are all serialized as tokens and concatenated. The LLM receives the current observation and the in-context demos and generates the next action.

    The LLM learns from demonstration that certain force thresholds signal failure (too much squeeze) or success (stable grasp). At test time on a new object configuration, the in-context demos provide the force signatures the model should replicate.

  • CVPR
    PR-MaGIC: Prompt Refinement Via Mask Decoder Gradient Flow For In-Context Segmentation — training-free prompt refinement using SAM decoder gradient flow for in-context visual segmentation

    Prompting SAM (Segment Anything) on a new visual task usually fails because the prompt (point, bounding box) does not encode task semantics. This work refines the prompt at test time using gradients through SAM's frozen decoder — updating the prompt representation, not the model weights.

    how it actually works

    The mechanism: SAM's decoder is frozen. An initial prompt is fed to SAM, producing a segmentation. A loss function measures how well the segmentation solves the task (e.g., how well it separates foreground from background). Backprop flows through the frozen decoder to the prompt representation, updating the prompt in-place.

    After a few gradient steps on the prompt, the refined prompt is used for final inference. This is in-context adaptation at the prompt level: no model training, but the prompt itself becomes task-specific.

Language-based task decomposition & hierarchical planning

robotics
the problem

Long-horizon tasks (20+ steps, 10+ minutes) exceed what any single skill or flat planner can handle. Robots need to decompose abstract goals into subtasks, and subtasks into primitive actions, maintaining consistent intent across the whole sequence.

the approaches

Hierarchical planning separates the what (decided by the LLM) from the how (decided by low-level controllers). The LLM excels at the semantic level — it knows that setting a table requires plates before glasses — while the motor controller handles the precise spatial execution.

The critical design question is where to cut the hierarchy. Too coarse and the LLM must handle details it cannot reason about well. Too fine and the LLM generates hundreds of steps where a single skill would suffice. The emerging answer is locality-invariant skills at the bottom — skills parameterized by local workspace rather than global pose — which dramatically reduces the number of distinct skills the LLM needs to name.

worked example — one concrete run
  1. Goal: 'Set the dining table for four'. This requires 20+ primitive actions across 5 object categories.
  2. LLM decomposes the goal into 6 high-level subgoals: [fetch_plates, place_plates, fetch_cutlery, place_cutlery, fetch_glasses, place_glasses].
  3. Each subgoal routes to a skill library: fetch_plates → grasp(plate_location) → navigate(table) → place(target_position).
  4. ManipGen uses locality-invariant policies for each skill: the same pick policy works on any plate location because it conditions on local workspace features, not global position.
  5. End-to-end success on novel table configurations: 61% (hierarchical LLM) vs 23% (flat policy) with zero additional demonstrations per configuration.
  • ROBO
    Local Policies Enable Zero-Shot Long-Horizon Manipulation — locality-invariant policies composed with foundation models for zero-shot multi-stage tasks

    Flat policies struggle with long-horizon tasks — the action space becomes too large and the learning curve too steep. Hierarchical composition buys generalization by decomposing the task into sub-tasks with locality-invariant skills: skills parameterized by local workspace features, not global pose.

    how it actually works

    The mechanism: The LLM decomposes a goal like 'set the table' into sub-goals: [fetch_plates, place_plates, fetch_cutlery, ...]. Each sub-goal routes to a skill. The skill is a learned policy that takes local workspace observations (e.g., features of the nearest plate relative to the gripper frame, not absolute position) and outputs an action.

    Locality invariance means the policy generalizes to different global positions: if the skill was trained on plates at (x=0.3m, y=0.1m), it works on plates at (x=0.8m, y=-0.2m) because it reasons in local frame features. The LLM handles the semantic sequencing; the skills handle the spatial execution.

  • ROBO
    MuST: Multi-Head Skill Transformer for Long-Horizon Dexterous Manipulation with Skill Progress — multi-head Transformer learns parallel motion primitives; learned progress value triggers skill-switching

    Long-horizon manipulation requires knowing when to switch from one skill to the next — a flat policy would need to predict skill-switching implicitly. This work uses a multi-head Transformer to learn multiple parallel motion primitives and a progress value that signals when each primitive is done.

    how it actually works

    The mechanism: A Transformer with multiple output heads learns latent representations of different motion primitives (reach, grasp, retract, place). A separate head predicts a progress value (0 to 1) that indicates how far through the current phase the policy is.

    When progress reaches 1, the system switches to the next head's outputs. Supervision comes from demonstrations annotated with skill boundaries: the model learns that progress=0→1 corresponds to 'reaching the object', then progress resets for the grasp phase. Long horizons become sequences of shorter, learnable sub-policies.

  • ROBO
    The Ingredients for Robotic Diffusion Transformers — Diffusion Transformer on multimodal language-annotated demonstrations for 1500+ timestep bimanual tasks

    Diffusion models generate high-quality data by iteratively denoising — they have proven powerful in image generation and NLP. This work applies diffusion to long-horizon robot trajectories: the model learns to denoise noisy action sequences over 1500+ timesteps using multimodal (language + demonstration) conditioning.

    how it actually works

    The mechanism: A sequence of actions (representing a 10+ minute bimanual task) is treated as a noisy signal. The diffusion model is trained to predict the noise added at each diffusion step, conditioned on language annotations of the demonstration and previous denoised actions. At test time, start with pure noise and iteratively denoise using the learned model.

    Key: The model learns long-range temporal dependencies through language grounding. The text annotation ('bimanual peg insertion, 15 steps') guides the denoising to produce coherent long-horizon plans.

  • ROBO
    COLLAGE: Collaborative Human-Agent Interaction Generation Using Hierarchical Latent Diffusion and Language Models — LLM generates motion planning cues guiding latent-space diffusion model for hierarchically-abstracted interaction sequences

    Human-robot interaction trajectories are hard to annotate because the robot must understand both human intent and geometric constraints. This work uses the LLM to generate motion planning cues (high-level guidance) that then steer a latent-space diffusion model to generate spatially valid interaction sequences.

    how it actually works

    The mechanism: The LLM reads a textual task description (e.g., 'human hands object to robot') and generates abstract cues: 'approach from the side', 'hand orientation east-to-west'. These cues are passed to a diffusion model that operates in a learned latent space of human-robot poses.

    The diffusion model iteratively refines a noisy sequence of pose pairs, using the LLM's cues to guide geometry-aware sampling. The result is a spatially coherent interaction sequence that respects constraints (collision avoidance, reachability) without the LLM needing to reason about 3D geometry.

Semantic navigation & object search

robotics
the problem

Hallucination mitigation & grounding

both
the problem

Multimodal language models generate fluent, confident statements that contradict the visual evidence in the image — describing objects that are not there, misidentifying spatial relations, or inventing attributes. Detecting and suppressing these errors without degrading correct outputs is the central challenge.

the approaches

Hallucination happens because the model's prior — the distribution learned from text — dominates the visual evidence when they conflict. A model that has read a million descriptions of white plates will output 'white' unless the visual signal is strong enough to override the linguistic prior. Contrastive decoding suppresses this by penalizing tokens that the model would produce even without the image.

Grounding-based methods take a different approach: force the model to cite the specific image region that justifies each claim. If the model cannot point to evidence for an assertion, it should not make the assertion. This is analogous to asking a student to cite their sources — it does not eliminate errors but makes them visible and correctable.

worked example — one concrete run
  1. Model is shown an image of a red apple on a blue plate. Asked: 'what color is the plate?'
  2. Without grounding: model outputs 'white' (hallucination — the most statistically common plate color at pretraining time).
  3. SEASON: compute a contrastive decoding score — penalize tokens whose probability rises when the image is replaced with a blank.
  4. Perceptual-evidence anchoring: enforce that the model cites an image patch before asserting an attribute — the patch acts as a verifiable evidence anchor.
  5. With grounding: model outputs 'blue'. Hallucination rate on ScienceQA drops from 28% to 11%.

both
the problem

Hard visual questions — counting, spatial reasoning, multi-hop inference — cannot be answered in a single forward pass. The model needs to decompose the question, inspect relevant image regions in sequence, and track the intermediate results before arriving at a final answer.

the approaches

Chain-of-thought reasoning works for language because intermediate steps make sub-problems explicit and easier to solve. The intermediate reasoning is not thrown away — it is grounded to specific scene observations that guide each subsequent step.

worked example — one concrete run
  1. Question: 'How many people are wearing red shirts and standing to the left of the door?' — requires counting, color recognition, and spatial grounding.
  2. Chain-of-thought step 1: model grounds 'the door' by attending to the doorframe region → extracts its x-coordinate (pixel 412).
  3. Step 2: model detects all people, filters those at x < 412 → 4 people on the left.
  4. Step 3: model checks shirt color for each of 4 people → 2 wearing red.
  5. Final answer: '2'. Without CoT the model outputs '5' (all red-shirt people, ignoring the spatial filter).

Parameter-efficient adaptation (LoRA & adapters)

both
the problem

Full fine-tuning of a 7-billion-parameter VLM requires storing and updating billions of gradient tensors — impractical per skill, per robot, or per domain. Parameter-efficient methods adapt the same backbone to many tasks by training only a small fraction of the weights.

the approaches

LoRA works by observing that the weight updates needed for a new task tend to have low intrinsic rank — they live in a small subspace of the full weight matrix. Decomposing the update into two small matrices (A times B) captures this subspace without storing or computing the full update. The pretrained weights stay frozen; only the low-rank adapters change.

For robots, this means the same base VLM can be adapted to a new skill with a tiny adapter trained on a hundred demonstrations, stored as a few megabytes, and swapped in and out at runtime. Multi-task systems store one adapter per skill and select the right one at inference time — essentially a mixture-of-LoRA over the same frozen backbone.

worked example — one concrete run
  1. Base model: a 7B-parameter VLM. Full fine-tune for a new robot task would require 28 GB of gradient memory.
  2. LoRA: decompose each weight update as ΔW = A·B where A ∈ ℝ^(d×r), B ∈ ℝ^(r×d), r=16.
  3. Trainable parameters: 2 × d × r per layer. For d=4096, r=16: 131K per layer vs 16.8M for full fine-tune → 99.2% reduction.
  4. Fine-tune on 500 robot demonstrations of a new pick-and-place task. Training time: 4 hours on 1 GPU vs 3 days for full fine-tune.
  5. Task success: 79% (LoRA) vs 81% (full fine-tune) — within 2% at 1% of the compute cost.

Model merging & multi-skill generalization

both
the problem

Training a single model on many skills simultaneously causes interference: skills that require contradictory behaviors degrade each other. Training one model per skill is expensive. Model merging combines independently trained single-skill weights into a unified model without joint retraining.

the approaches

Model merging treats the fine-tuned weight delta (the task vector) as a semantic artifact that can be added to, subtracted from, or combined with other task vectors. This works because fine-tuning from the same base tends to update different subspaces for different skills — the interference is real but manageable with sparsity or routing.

For robots, merging is attractive because it avoids the combinatorial explosion of maintaining one model per (skill, embodiment, environment) combination. A generalist VLA built by merging a library of specialist models retains most of each specialist's performance at a fraction of the storage and compute cost.

worked example — one concrete run

the problem

A single LLM forward pass can reason but cannot search the web, run code, or query a database. Agentic systems give the model tools — search, Python execution, perception APIs — and ask it to plan a sequence of tool calls that together accomplish a goal the model cannot complete in one step.

For robots, the tools are the robot's own sensors and actuators: perception APIs, motion planners, force sensors, maps. An agentic robot controller calls these tools sequentially, building up a plan step by step based on what each tool returns. Use a ViT-style encoder adapted for larger spatial dimensions (satellite images are 512×512 or larger) and multiple spectral channels. Output patch embeddings E_v ∈ ℝ^(N_patches × d).
    2. Text encoder: processes geospatial descriptions T (e.g., 'urban area with dense housing, major road, small park' or 'agricultural region, corn fields, irrigation' or 'forested mountain terrain with sparse settlements'). Use a standard transformer text encoder: E_t ∈ ℝ^(L × d).
    3. Diffusion decoder (instead of autoregressive): model the distribution of output text tokens p(T | I_sat) via a reverse diffusion process. Start with Gaussian noise, iteratively denoise over K steps. At each step t_denoise ∈ {K, K-1, ..., 1}, the denoiser network conditions on [E_v, noise_t] and predicts the next token distribution (or soft token embeddings). Diffusion allows bidirectional context: later words can influence earlier words through the iterative refinement.
    4. Pretraining: contrastive learning between E_v and E_t (maximize similarity of matching image-text pairs, minimize for negatives) + diffusion decoding loss (denoise objective). Train on 1.2M satellite image-text pairs.
    5. Downstream: for land-use classification, fine-tune the model on a smaller labeled dataset (1-10K images). The pretrained knowledge of 'what do urban, agricultural, and forest regions look like from above' transfers.

    Why it works: satellite imagery is visually distinctive but underrepresented in web-scale pretraining. Domain-specific pretraining on 1.2M examples teaches the model geospatial semantics. Diffusion decoding (bidirectional) is well-suited to satellite imagery, where global context matters—the land-use type of a region emerges from observing the whole area, not sequentially generating tokens left-to-right. The multispectral input (NIR, SWIR) is directly used, avoiding RGB-only assumptions. The result: a model that understands geographic patterns without requiring hand-crafted features (spectral indices, texture descriptors).

    From Panel to Pixel: Zoom-In Vision-Language Pretraining from Biomedical Scientific Literature — hierarchical figure-panel-patch supervision from biomedical papers; learns fine-grained scientific image understanding

    Biomedical papers contain figures—panels of microscopy images, histology slides, medical scans—arranged in multi-panel layouts (e.g., a 3×2 grid with different treatments or time points). Each panel shows a specific biological phenomenon. General VLMs rarely see this structure; they treat figures as monolithic. A biomedical VLM needs to understand: what is the role of panel (B) relative to panel (A)? How does the zoomed-in view in panel (C) relate to the full image in panel (A)? This paper extracts a hierarchical figure-panel-patch supervision signal from biomedical papers: for each figure, use OCR and layout detection to identify panels and their captions. Then construct training triplets: (full figure, individual panel, zoomed-in region from the panel). Supervise the model: given a full figure, can you identify which panel shows a particular detail? Given a panel, can you describe what part is zoomed in? The payoff is a VLM specialized for fine-grained biomedical image analysis—it understands hierarchical structure and can reason about parts and wholes.

    how it actually works

    The mechanism: Hierarchical supervision from paper figures; panel-to-zoom relationships.

    1. Data collection: mine 100K+ biomedical papers (from PubMed, arXiv, journals with open figures). Use computer vision (layout detection) to identify figures and extract panel boundaries via document layout analysis.
    2. OCR and caption extraction: for each figure, use OCR to read the caption (e.g., 'Figure 3: Effects of treatment A on cell morphology. (A) Control, (B) Low dose, (C) High dose, (D) Quantification.'). Parse panel labels (A), (B), (C), etc. from the layout.
    3. Triplet construction: (1) Full figure (all panels as context), (2) Individual panel (e.g., the zoomed image showing high-dose treatment), (3) Sub-patch within the panel (a specific cell or region highlighted in the caption or layout). Create triplets: (full_image, panel_image, detailed_patch).
    4. Supervision: train the model with three objectives: (1) Match full image to caption (image-text alignment), (2) Given full image and description of panel (B), retrieve panel (B)'s image (coarse-grained), (3) Given a panel and a description of a detail, retrieve the detailed patch (fine-grained).
    5. Hierarchical embedding: the model learns to embed at multiple granularities—full figure at coarse level, panels at mid-level, patches at fine level—all in the same embedding space.

    Why it works: biomedical papers provide free supervision—the figure layouts and captions encode hierarchical relationships (full image → panel → detail). By mining this structure, you get millions of training examples without manual labeling. The model learns that biomedical images have hierarchical structure (zooming in reveals finer cellular or molecular details). This transfers to downstream tasks: tissue classification, cell detection, pathology image analysis. The hierarchical embeddings enable fine-grained retrieval and comparison—essential for research (finding similar experimental results across papers) and clinical work (comparing before/after or control/treatment images).

Part IV

Where it stands

Foundation models are the fastest-moving area in robotics — and several fundamental questions remain genuinely open:

Hallucination with no physical correction loop. LLMs generate plausible-sounding plans that violate physics or geometry. Without tight feedback from perception and execution, there is no mechanism to catch these errors before they cause a robot to fail or cause harm.
Latency vs control frequency. An LLM call takes 50–500 ms; a low-level robot controller runs at 100–1000 Hz. Current architectures separate planning (slow, LLM) from execution (fast, learned policy), but the interface between them is fragile when the world changes faster than the LLM can re-plan.
Evaluation of open-ended task success. When the task is specified in language ('make dinner'), what counts as success? Evaluating LLM-based robot policies requires natural-language success criteria, which is itself a grounding problem. There is no agreed-upon benchmark that captures the full distribution of real household tasks.
Sim-to-real for LLM-guided policies. Simulating the physical world for training is one problem; simulating the linguistic context (user instructions, failure descriptions) is a different problem that has received less attention. LLM-guided policies that work in simulation often fail when users phrase instructions differently in the real world.
Safety guarantees. Symbolic planners offer formal correctness proofs; LLM-generated plans are probabilistic and cannot be formally verified. Combining LLM flexibility with the safety properties of formal methods — without sacrificing the generalization benefit — is an open architecture problem.
