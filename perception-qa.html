A perception stack you can trust

A recogniser with high test accuracy is not yet trustworthy: it fuses faulty sensors, answers unfamiliar inputs with false confidence, over-reports certainty, and goes silently blind when the world drifts. Four checks close those gaps — each a plain rule, run and measured on real perception experiments. Built in the demo-package style of the CV project: a tested, reusable core behind every stage.

This is the sensing side of a trilogy: what to learn → whether to trust what you sense → how to act on it safely. Accuracy is table stakes; these checks are what let a planner rely on the number a perception hands it.

1

Sensor Fusion & Agreement

A robot reads the same quantity from two noisy sensors and has to commit to one number. Average them and a single faulty sensor drags the estimate off; trust the 'better' one and you throw away information the other one had.

Trust a perception only where independent sources agree; weight them by their noise.
RMSE — sensor A / sensor B0.399 / 0.248
RMSE — noise-weighted fusion0.211
fault caught (recall) / false alarm90% / 0.1%
RMSE under fault — naive vs gated0.793 vs 0.309

Sensor A alone has RMSE 0.399, the better sensor B 0.248; noise-weighted fusion beats both at 0.211. When B faults on 20% of readings, disagreement flags 90% of the faults at a 0.1% false-alarm rate — so agreement-gated fusion holds RMSE at 0.309 where fusing the fault in blows it up to 0.793.

2

Out-of-Distribution Novelty Check

A perception model learned to recognise a fixed world. In deployment it will meet inputs from outside that world — a new object, a new lighting, a sensor it never saw — and answer them with the same confidence it uses on familiar ones.

A perception model is valid only on inputs like its training set; flag the rest.
novel inputs caught (recall)100%
false alarms on familiar inputs5%
separation (AUROC)0.999

On a stream of in-distribution and novel inputs, the distance check flags 100% of the novel ones while false-alarming on only 5% of familiar inputs — an AUROC of 0.999 separating the two.

3

Confidence Calibration

A downstream planner treats the perception's confidence as a probability — it slows down when the detector is unsure. But a modern network trained hard is overconfident: it reports 99% on calls it gets wrong a quarter of the time, so the planner trusts it exactly when it shouldn't.

A confidence is only useful if it matches reality; measure the gap and rescale it.
accuracy (unchanged)75%
calibration error — before0.192
calibration error — after0.068
fitted temperature9.43

The overfit classifier is 75% accurate but badly miscalibrated: expected calibration error 0.192. A single temperature (T=9.43, i.e. its logits were ~9× too sharp) cuts calibration error to 0.068 — 2.8× more honest — without touching accuracy.

4

Covariate-Drift Monitor

In production there are no labels, so accuracy is invisible. The camera slowly fogs, the season changes, the floor gets glossier — the input distribution drifts, accuracy quietly falls, and nothing in the pipeline says a word until something downstream breaks.

Watch the input distribution; a silent covariate shift is a failure before the metrics move.
accuracy — before / after drift85% / 59%
flagged fraction — before / after6% / 42%
labels needed by the monitornone

Under a covariate shift the classifier's accuracy silently falls from 85% to 59% — a 26-point drop no one could see without labels. The label-free monitor catches it: the flagged fraction jumps from 6% to 42% — a 7× rise you can alarm on immediately.

How this was built. Real experiments (scripts/perception_qa_experiments.py, NumPy + a tiny CPU torch classifier) produce the numbers above. Each stage is also a small tested demo package under source-code/learning/perception-qa/<stage>/ — a reusable core.js carrying the rule, with node assert-tests — so the insight is a primitive you can drop onto your own perception logs.
